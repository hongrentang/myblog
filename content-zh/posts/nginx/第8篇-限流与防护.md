## 为什么需要限流？

没有限流的服务就像没有护栏的桥——当流量超出设计容量时：

- 数据库连接池耗尽
- CPU 打满，响应时间飙升
- 服务雪崩：一台挂了，流量转移到其他机器，引发连锁反应
- 恶意攻击：暴力破解、爬虫、DDoS

Nginx 内置的限流能力可以在请求到达后端之前就进行控制。

---

## 一、连接数限制（limit_conn）

限制同一 IP 的并发连接数：

```nginx
http {
    limit_conn_zone $binary_remote_addr zone=conn_zone:10m;

    server {
        location / {
            limit_conn conn_zone 10;        # 每个 IP 最多 10 个并发连接
            limit_conn_status 503;           # 超限时返回 503
            limit_conn_log_level warn;       # 日志级别
        }

        location /download/ {
            limit_conn conn_zone 5;          # 下载区限制更严格
        }
    }
}
```

`$binary_remote_addr` 比 `$remote_addr` 占用更少内存（10MB 约存 16 万个 IP）。

### 按域名限制

```nginx
http {
    limit_conn_zone $server_name zone=site_zone:10m;

    server {
        location / {
            limit_conn site_zone 100;  # 整个站点最多 100 个并发
        }
    }
}
```

## 二、请求频率限制（limit_req）

限制每秒的请求数，基于漏桶算法：

```nginx
http {
    # 定义限制区域：每个 IP 每秒最多 1 个请求
    limit_req_zone $binary_remote_addr zone=req_zone:10m rate=1r/s;

    server {
        location / {
            limit_req zone=req_zone;
            limit_req_status 429;             # 返回 Too Many Requests
            limit_req_log_level warn;
        }
    }
}
```

### 漏桶 vs 令牌桶

**漏桶（默认）**：

```nginx
limit_req zone=req_zone burst=5;
```

```
请求到达 → [桶] → 匀速处理
固定出口速率（1r/s），突发请求最多排队 5 个，超出的丢弃
```

**令牌桶（添加 nodelay）**：

```nginx
limit_req zone=req_zone burst=5 nodelay;
```

```
请求到达 → 取出令牌 → 立即处理
突发请求只要有令牌就立刻处理，处理完这 5 个后恢复 1r/s
```

### 实际例子

```nginx
http {
    # 正常 API：每 IP 每秒 10 个
    limit_req_zone $binary_remote_addr zone=api:10m rate=10r/s;

    # 登录接口：每 IP 每分钟 5 个（防暴力破解）
    limit_req_zone $binary_remote_addr zone=login:10m rate=5r/m;

    # 爬虫限制：按 User-Agent 限流
    limit_req_zone $http_user_agent zone=crawler:10m rate=1r/s;

    server {
        location /api/ {
            limit_req zone=api burst=20 nodelay;
        }

        location /login {
            limit_req zone=login burst=3;
            limit_req_status 429;
        }
    }
}
```

rate 支持的单位：`r/s`（每秒请求数）、`r/m`（每分钟请求数）。

## 三、限制请求体大小

```nginx
# 控制客户端请求体最大大小
client_max_body_size 10m;

# 请求体缓冲区大小，小了会写入临时文件
client_body_buffer_size 128k;

# 请求体超时
client_body_timeout 60s;
```

典型场景：

```nginx
server {
    # 普通接口
    location /api/ {
        client_max_body_size 1m;
    }

    # 文件上传接口
    location /upload/ {
        client_max_body_size 100m;
        client_body_buffer_size 1m;  # 超过 1MB 写入临时文件
        client_body_timeout 120s;
    }
}
```

---

## 四、限制请求头

```nginx
# 请求头缓冲区
client_header_buffer_size 1k;
large_client_header_buffers 4 8k;

# 请求头超时
client_header_timeout 60s;
```

- `client_header_buffer_size`：默认 1KB，超过用 `large_client_header_buffers`
- `large_client_header_buffers`：4 个 8KB 缓冲区，超过返回 414

常见过大的请求头场景：

- Cookie 过大（4K+）
- 自定义认证头过长

## 五、超时设置

```nginx
# 客户端连接
keepalive_timeout 65;       # keepalive 超时
keepalive_requests 100;     # 一个 keepalive 连接的最大请求数

# 读取请求体
client_body_timeout 60s;

# 读取请求头
client_header_timeout 60s;

# 向后端发起连接
proxy_connect_timeout 30s;

# 读取后端响应
proxy_read_timeout 60s;

# 发送数据到后端
proxy_send_timeout 60s;
```

## 六、IP 黑/白名单

### 白名单模式

```nginx
geo $whitelist {
    default 0;
    192.168.1.0/24 1;
    10.0.0.0/8 1;
    103.235.46.39 1;  # 合作方 IP
}

server {
    location /admin {
        if ($whitelist = 0) {
            return 403;
        }
        # 管理员面版配置...
    }
}
```

### 黑名单模式

```nginx
geo $blocked_ip {
    default 0;
    1.2.3.4 1;
    5.6.7.0/24 1;
}

server {
    if ($blocked_ip) {
        return 444;  # 关闭连接不返回任何响应
    }
}
```

## 八、爬虫管理

### 限制爬虫频率

```nginx
http {
    # 根据 User-Agent 限流
    limit_req_zone $http_user_agent zone=crawler:10m rate=1r/s;

    server {
        location / {
            limit_req zone=crawler burst=3 nodelay;

            # 为友好爬虫设置例外
            if ($http_user_agent ~* (Googlebot|Bingbot|Baiduspider)) {
                limit_req zone=;  # 移除限制
                set $crawler_bypass 1;
            }
        }
    }
}
```

### 拦截恶意爬虫

```nginx
# 识别并拦截已知恶意爬虫
if ($http_user_agent ~* (Semrush|AhrefsBot|MJ12bot|DotBot)) {
    return 403;
}

# 验证爬虫 IP（反向 DNS 验证）
server {
    location / {
        if ($http_user_agent ~* Googlebot) {
            # 检查 IP 是否属于 Google
            # 需要配合 geo 模块使用
        }
    }
}
```

## 九、DDoS 防护措施

### 基础防护组合

```nginx
http {
    # 1. 限流
    limit_req_zone $binary_remote_addr zone=ddos:10m rate=30r/s;
    limit_conn_zone $binary_remote_addr zone=conn:10m;

    # 2. 限制连接速率（慢速攻击防护）
    limit_rate 50k;  # 默认单连接速率
    limit_rate_after 1m;  # 前 1MB 不限速

    # 3. 超时切断
    client_body_timeout 10s;
    client_header_timeout 10s;
    keepalive_timeout 10s;

    server {
        listen 80;
        server_name example.com;

        location / {
            limit_req zone=ddos burst=10 nodelay;
            limit_conn conn 5;
            proxy_pass http://backend;
        }
    }
}
```

### 屏蔽非标准请求

```nginx
# 只允许 GET/HEAD/POST
if ($request_method !~ ^(GET|HEAD|POST)$) {
    return 405;
}

# 屏蔽没有 User-Agent 的请求（通常是恶意工具）
if ($http_user_agent = "") {
    return 403;
}
```

## 十、反向代理层面的安全配置

```nginx
server {
    # 隐藏 Nginx 版本号
    server_tokens off;

    # 禁止 iframe（防点击劫持）
    add_header X-Frame-Options "SAMEORIGIN" always;

    # 禁止 MIME 嗅探
    add_header X-Content-Type-Options "nosniff" always;

    # CSP 内容安全策略
    add_header Content-Security-Policy "default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline';" always;

    # 限制 HTTP 方法
    limit_except GET HEAD POST {
        deny all;
    }

    # 禁止访问隐藏文件
    location ~ /\. {
        deny all;
        return 404;
    }

    # 禁止访问敏感文件
    location ~* (\.env|\.git|\.svn|composer\.json|package\.json) {
        deny all;
        return 404;
    }

    # 限制访问来源
    location /admin {
        allow 192.168.1.0/24;
        allow 10.0.0.0/8;
        deny all;
        auth_basic "Admin Area";
        auth_basic_user_file /etc/nginx/.htpasswd;
    }
}
```

## 监控限流状态

在日志格式中添加限流信息：

```nginx
log_format limit '$remote_addr - $remote_user [$time_local] "$request" '
                '$status $body_bytes_sent "$http_referer" '
                '"$http_user_agent" '
                'limit_req="$limit_req_status" limit_conn="$limit_conn_status"';

access_log /var/log/nginx/access.log limit;
```

查看被限流的请求：

```bash
grep "LIMIT" /var/log/nginx/error.log
grep '"limit_req="1"' /var/log/nginx/access.log  # 被限流的请求
```
