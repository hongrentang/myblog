## 配置文件结构回顾

Nginx 的配置遵循**指令**和**块**的层次结构：

```
指令名 参数;
块名 { ... }
```

每个指令以分号结尾，块用花括号包裹。

---

## 搭建一个静态文件服务器

### 最简单的例子

```nginx
server {
    listen 80;
    server_name static.example.com;

    root /var/www/static;
    index index.html index.htm;
}
```

将 HTML 文件放入 `/var/www/static`，浏览器访问 `http://static.example.com` 即可看到内容。

### 完整的静态服务器配置

```nginx
server {
    listen 80;
    server_name static.example.com;
    root /var/www/static;
    index index.html;

    # 关闭目录列表（安全考虑）
    autoindex off;

    # 文件过期时间
    location ~* \.(jpg|jpeg|png|gif|ico|css|js)$ {
        expires 30d;
        add_header Cache-Control "public, no-transform";
    }

    # 字体文件
    location ~* \.(woff|woff2|ttf|otf|eot)$ {
        expires 30d;
        add_header Cache-Control "public, no-transform";
    }

    # 禁止访问隐藏文件
    location ~ /\. {
        deny all;
        return 404;
    }
}
```

## 配置指令详解

### listen

监听端口或 Unix Socket：

```nginx
listen 80;                          # IPv4
listen [::]:80;                     # IPv6
listen 443 ssl;                     # HTTPS
listen 8080 default_server;         # 默认服务器
listen unix:/var/run/nginx.sock;    # Unix Socket
```

### server_name

域名匹配方式：

```nginx
server_name example.com;                 # 精确匹配
server_name *.example.com;               # 通配符
server_name .example.com;                # 匹配 example.com 和 *.example.com
server_name ~^www\d\.example\.com$;      # 正则匹配
server_name "";                          # 没有 Host 头时匹配
```

多个域名用空格分隔：`server_name site1.com site2.com;`

### location

URI 匹配规则（第7篇会深入讲解）：

```nginx
location / {                        # 前缀匹配
    ...
}

location = /exact {                 # 精确匹配
    ...
}

location ~ \.php$ {                 # 正则匹配（大小写敏感）
    ...
}

location ~* \.(jpg|png)$ {         # 正则匹配（大小写不敏感）
    ...
}

location ^~ /static/ {             # 优先前缀匹配
    ...
}
```

### root vs alias

这两个指令极易混淆：

```nginx
# root：将完整 URI 追加到路径后
location /images {
    root /var/www;
    # 请求 /images/logo.png → /var/www/images/logo.png
}

# alias：将 location 匹配部分替换为指定路径
location /images {
    alias /var/www/uploads;
    # 请求 /images/logo.png → /var/www/uploads/logo.png
}
```

**关键区别**：`root` 不会丢弃 location 匹配的部分，`alias` 会。

## 处理错误页面

```nginx
server {
    error_page 404 /404.html;
    error_page 500 502 503 504 /50x.html;

    location = /404.html {
        root /var/www/errors;
        internal;       # 只能通过内部重定向访问
    }

    location = /50x.html {
        root /var/www/errors;
        internal;
    }
}
```

自定义错误页面时，记得用 `internal` 防止用户直接访问。

## 访问控制

### IP 白名单

```nginx
location /admin {
    allow 192.168.1.0/24;
    allow 10.0.0.1;
    deny all;
}
```

### 密码认证

```bash
# 创建密码文件
sudo htpasswd -c /etc/nginx/.htpasswd admin
```

```nginx
location /admin {
    auth_basic "Restricted Area";
    auth_basic_user_file /etc/nginx/.htpasswd;
}
```

### 限制请求方法

```nginx
if ($request_method !~ ^(GET|HEAD|POST)$) {
    return 405;
}
```

更推荐用 `limit_except`：

```nginx
location /api {
    limit_except GET POST {
        deny all;
    }
}
```

## 包含指令与配置拆分

把配置拆分成多个文件是好习惯：

```nginx
# 主配置
include /etc/nginx/conf.d/*.conf;

# 专门放 upstream 定义
include /etc/nginx/upstreams/*.conf;
```

常见拆分方式：

```
/etc/nginx/
├── nginx.conf                # 全局配置
├── conf.d/
│   ├── example.com.conf      # 每个站点一个文件
│   └── api.example.com.conf
├── upstreams/
│   ├── backend.conf          # 后端服务组
│   └── cache.conf
└── snippets/
    ├── ssl.conf              # SSL 通用配置
    ├── gzip.conf             # Gzip 通用配置
    └── security.conf         # 安全相关配置
```

## 常用变量

Nginx 提供了大量内置变量，在配置中可以直接使用：

```nginx
# 在日志格式中使用
log_format main '$remote_addr - $remote_user [$time_local] "$request" '
                '$status $body_bytes_sent "$http_referer" '
                '"$http_user_agent"';

# 在 location 中判断
location / {
    # 根据 User-Agent 做不同处理
    if ($http_user_agent ~* (curl|wget)) {
        return 403;
    }
}
```

**常用变量：**

| 变量 | 说明 |
|------|------|
| `$remote_addr` | 客户端 IP |
| `$remote_user` | 基础认证用户名 |
| `$time_local` | 本地时间 |
| `$request` | 完整的请求行 (方法 + URI + 协议) |
| `$status` | 响应状态码 |
| `$body_bytes_sent` | 响应 body 字节数 |
| `$http_referer` | Referer 头 |
| `$http_user_agent` | User-Agent 头 |
| `$http_x_forwarded_for` | X-Forwarded-For 头 |
| `$host` | 请求的 Host |
| `$uri` | 当前 URI（可能已被 rewrite 修改） |
| `$request_uri` | 原始 URI（未修改） |
| `$scheme` | 协议（http/https） |
| `$server_name` | 匹配到的 server_name |

## 调试技巧

```bash
# 检查配置语法
nginx -t

# 查看所有配置（解析后）
nginx -T

# 测试 location 匹配
# 在 server 块中添加：
location /test {
    return 200 "matched: /test\n";
}
# 然后 curl http://localhost/test

# 查看完整配置的上下文
nginx -T 2>&1 | grep -A5 "server_name example.com"
```
