## 日志体系

Nginx 有两类日志：

- **访问日志（access_log）**：记录每次请求的详细信息
- **错误日志（error_log）**：记录 Nginx 运行时的错误和警告

---

## 一、访问日志

### 默认配置

```nginx
http {
    log_format main '$remote_addr - $remote_user [$time_local] "$request" '
                    '$status $body_bytes_sent "$http_referer" '
                    '"$http_user_agent" "$http_x_forwarded_for"';

    access_log /var/log/nginx/access.log main;
}
```

### 自定义日志格式

```nginx
log_format json escape=json '{'
    '"time_local":"$time_local",'
    '"remote_addr":"$remote_addr",'
    '"remote_user":"$remote_user",'
    '"request":"$request",'
    '"status":$status,'
    '"body_bytes_sent":$body_bytes_sent,'
    '"request_time":$request_time,'
    '"upstream_response_time":"$upstream_response_time",'
    '"http_referer":"$http_referer",'
    '"http_user_agent":"$http_user_agent",'
    '"http_x_forwarded_for":"$http_x_forwarded_for",'
    '"cache_status":"$upstream_cache_status"'
'}';
```

JSON 格式的日志更方便被日志收集系统（ELK、Loki）解析。

### 条件日志

```nginx
# 不记录健康检查请求
map $uri $loggable {
    /health 0;
    default 1;
}

server {
    access_log /var/log/nginx/access.log main if=$loggable;
}
```

### 按域名分拆日志

```nginx
http {
    log_format main '...';

    server {
        server_name example.com;
        access_log /var/log/nginx/example.com.access.log main;
    }

    server {
        server_name blog.example.com;
        access_log /var/log/nginx/blog.example.com.access.log main;
    }
}
```

### 缓冲区写入

高并发下，日志先写入缓冲区再批量写入磁盘，可提升性能：

```nginx
access_log /var/log/nginx/access.log main buffer=64k flush=5s;
```

- `buffer=64k`：缓冲区 64KB，满了才写
- `flush=5s`：即使没满，最多等 5 秒也写

## 二、错误日志

### 配置

```nginx
error_log /var/log/nginx/error.log warn;
```

### 日志级别

从低到高：

| 级别 | 说明 | 使用场景 |
|------|------|---------|
| `debug` | 调试信息 | 排查配置问题 |
| `info` | 一般信息 | 开发环境 |
| `notice` | 重要通知 | 一般监控 |
| `warn` | 警告 | **推荐生产环境** |
| `error` | 错误 | 仅记录错误 |
| `crit` | 严重错误 | 紧急问题 |
| `alert` | 警报 | 立即处理 |
| `emerg` | 紧急 | 系统不可用 |

### 按级别拆分

```nginx
error_log /var/log/nginx/error.log warn;
error_log /var/log/nginx/error_debug.log debug;  # 调试信息单独一个文件
```

## 三、日志变量大全

### 客户端信息

| 变量 | 说明 |
|------|------|
| `$remote_addr` | 客户端 IP |
| `$remote_user` | HTTP 认证用户名 |
| `$http_user_agent` | 客户端 UA |
| `$http_referer` | 来源 URL |
| `$http_x_forwarded_for` | 转发链 IP |

### 请求信息

| 变量 | 说明 |
|------|------|
| `$request` | 完整请求行 |
| `$request_method` | 请求方法 |
| `$request_uri` | 原始 URI |
| `$uri` | 当前 URI（rewrite 后） |
| `$args` | 查询参数 |
| `$arg_name` | 指定参数值 |
| `$host` | 请求的 Host |

### 响应信息

| 变量 | 说明 |
|------|------|
| `$status` | HTTP 状态码 |
| `$body_bytes_sent` | 响应体大小 |
| `$bytes_sent` | 总发送字节数 |
| `$content_length` | 响应 Content-Length |
| `$content_type` | 响应 Content-Type |

### 性能指标

| 变量 | 说明 |
|------|------|
| `$request_time` | 请求处理总时间（秒）|
| `$upstream_response_time` | 后端响应时间（秒）|
| `$upstream_connect_time` | 连接后端耗时 |
| `$upstream_header_time` | 后端返回头部耗时 |
| `$pipe` | 是否使用管道传输 |
| `$connection` | 连接序列号 |
| `$connection_requests` | 当前连接请求数 |

## 四、日志分析

### 常用分析命令

```bash
# 统计 IP 访问次数（取 top 10）
awk '{print $1}' /var/log/nginx/access.log | sort | uniq -c | sort -rn | head -10

# 统计 PV
wc -l /var/log/nginx/access.log

# 统计 UV（独立 IP）
awk '{print $1}' /var/log/nginx/access.log | sort -u | wc -l

# 统计请求状态码分布
awk '{print $9}' /var/log/nginx/access.log | sort | uniq -c | sort -rn

# 统计请求耗时分布（JSON 格式日志，提取 request_time）
grep -o '"request_time":[0-9.]*' access.log | cut -d: -f2 | awk '{if($1>3) count++} END{print count " requests > 3s"}'

# 查找最慢的 10 个请求
awk '{print $NF, $0}' /var/log/nginx/access.log | sort -rn | head -10

# 统计某个 URL 的访问量
awk '$7 ~ /^\/api\/users/ {count++} END{print count}' /var/log/nginx/access.log

# 统计每分钟请求数
awk '{print $4}' /var/log/nginx/access.log | cut -d: -f1-2 | sort | uniq -c | sort -rn

# 查找 5xx 错误
awk '$9 ~ /^5/ {print $1, $7, $9}' /var/log/nginx/access.log | head -20
```

### 使用 goaccess 可视化分析

```bash
# 安装
sudo apt install goaccess

# 运行交互式分析
goaccess /var/log/nginx/access.log --log-format=COMBINED

# 生成 HTML 报告
goaccess /var/log/nginx/access.log --log-format=COMBINED -o report.html
```

## 五、日志轮转（logrotate）

Nginx 不自带日志切割功能，依赖系统的 logrotate。

```bash
# /etc/logrotate.d/nginx
/var/log/nginx/*.log {
    daily                   # 每天轮转
    rotate 30               # 保留 30 天
    dateext                 # 文件名加日期
    missingok               # 日志不存在不报错
    notifempty              # 空文件不轮转
    compress                # 压缩旧日志
    delaycompress           # 延迟一天压缩
    sharedscripts           # 所有日志共享一个脚本
    postrotate
        [ -f /var/run/nginx.pid ] && kill -USR1 `cat /var/run/nginx.pid`
    endscript
}
```

手动测试：

```bash
sudo logrotate -f /etc/logrotate.d/nginx
```

**注意**：轮转后必须发送 `USR1` 信号让 Nginx 重新打开日志文件，否则 Nginx 会继续往已被重命名的文件里写。

## 六、日志安全

### 避免敏感信息泄露

```nginx
log_format secure '$remote_addr - $remote_user [$time_local] "$request" '
                  '$status $body_bytes_sent';

access_log /var/log/nginx/access.log secure;
```

不要在日志中记录：
- 密码或令牌（通常在 `$request` 中，如果参数带密码要考虑脱敏）
- 完整的 Cookie
- 个人身份信息（PII）

### 日志权限

```bash
# 确保日志目录权限合理
chmod 750 /var/log/nginx
chmod 640 /var/log/nginx/*.log
chown -R www-data:adm /var/log/nginx
```

## 七、统一日志收集

生产环境中，单机日志分析效率太低，需要统一收集到中心化平台。

### Filebeat 配置示例

```yaml
# filebeat.yml
filebeat.inputs:
  - type: log
    paths:
      - /var/log/nginx/access.log
    fields:
      type: nginx-access
    json.keys_under_root: true
    json.overwrite_keys: true
    json.add_error_key: true

output.elasticsearch:
  hosts: ["http://elasticsearch:9200"]
  index: "nginx-access-%{+yyyy.MM.dd}"
```

### 日志架构推荐

```
Nginx → 文件 → Filebeat → Elasticsearch → Kibana（可视化）
                  ↘ Kafka → Logstash → Elasticsearch（复杂管道）
Nginx → 文件 → Promtail → Loki → Grafana（轻量方案）
```

小团队推荐 Loki + Grafana 方案，部署简单，成本低。
