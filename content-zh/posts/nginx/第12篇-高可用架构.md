## 单点故障问题

Nginx 本身也会挂。如果只有一台 Nginx，它挂了整个服务就不可用。

**解决方案**：Nginx 主备模式 —— 两台 Nginx，一台提供服务，另一台监控，主节点挂了备节点自动接管。

```
                    ┌─ Nginx 主 (192.168.1.10)
用户 → VIP (10.0.0.100) ─┼─ Nginx 备 (192.168.1.11)
                    └─ 实际请求路径
```

用户访问的是虚拟 IP（VIP），VIP 始终指向当前可用的 Nginx。

---

## Keepalived 简介

Keepalived 是一个高可用解决方案，通过 **VRRP（虚拟路由冗余协议）** 实现：

- 主节点定期发送心跳（VRRP 广播）
- 备节点如果收不到心跳，就接管 VIP
- VIP 切换对客户端透明

## 主节点配置

```bash
# /etc/keepalived/keepalived.conf

global_defs {
    router_id NGINX_MASTER      # 路由标识，唯一
    script_user root
    enable_script_security
}

# 健康检查脚本
vrrp_script check_nginx {
    script "/etc/keepalived/check_nginx.sh"
    interval 2                  # 每 2 秒检查一次
    timeout 3                   # 脚本超时 3 秒
    weight -50                  # 检查失败权重减 50
    rise 2                      # 连续 2 次成功才认为健康
    fall 3                      # 连续 3 次失败才认为不健康
}

vrrp_instance VI_1 {
    state MASTER                # 主节点
    interface eth0              # 监听的网卡
    virtual_router_id 51        # 虚拟路由 ID（主备必须一致）
    priority 150                # 优先级，越高越可能成为主
    advert_int 1                # 心跳间隔（秒）
    nopreempt                   # 不抢占（主恢复后不自动夺回 VIP）

    authentication {
        auth_type PASS
        auth_pass 1234          # 认证密码
    }

    virtual_ipaddress {
        10.0.0.100/24 dev eth0 label eth0:vip  # VIP
    }

    track_script {
        check_nginx
    }

    notify_master /etc/keepalived/scripts/master.sh   # 成为主时执行
    notify_backup /etc/keepalived/scripts/backup.sh   # 成为备时执行
    notify_fault  /etc/keepalived/scripts/fault.sh    # 故障时执行
}
```

## 备节点配置

```bash
# /etc/keepalived/keepalived.conf（备节点）

global_defs {
    router_id NGINX_BACKUP      # 与主节点不同
}

vrrp_script check_nginx {
    script "/etc/keepalived/check_nginx.sh"
    interval 2
    timeout 3
    weight -50
}

vrrp_instance VI_1 {
    state BACKUP                # 备节点
    interface eth0
    virtual_router_id 51        # 必须与主节点一致
    priority 100                # 优先级低于主节点
    advert_int 1

    authentication {
        auth_type PASS
        auth_pass 1234
    }

    virtual_ipaddress {
        10.0.0.100/24 dev eth0 label eth0:vip
    }

    track_script {
        check_nginx
    }
}
```

## Nginx 健康检查脚本

```bash
#!/bin/bash
# /etc/keepalived/check_nginx.sh

# 方法1：检查进程是否存在
if ! pgrep -x nginx > /dev/null; then
    # 尝试重启 Nginx
    systemctl start nginx

    # 等 2 秒再检查
    sleep 2

    # 重启失败则让 Keepalived 切换备机
    if ! pgrep -x nginx > /dev/null; then
        exit 1
    fi
fi

# 方法2：检查 HTTP 响应（更可靠）
HTTP_CODE=$(curl -s -o /dev/null -w "%{http_code}" http://127.0.0.1/health 2>/dev/null)
if [ "$HTTP_CODE" != "200" ]; then
    systemctl restart nginx
    sleep 2
    HTTP_CODE=$(curl -s -o /dev/null -w "%{http_code}" http://127.0.0.1/health 2>/dev/null)
    if [ "$HTTP_CODE" != "200" ]; then
        exit 1
    fi
fi

exit 0
```

```bash
# 赋予执行权限
chmod +x /etc/keepalived/check_nginx.sh
```

## 启动与验证

```bash
# 启动 Keepalived（主备节点都执行）
sudo systemctl start keepalived
sudo systemctl enable keepalived

# 查看 VIP 在哪台机器上
ip addr show eth0 | grep 10.0.0.100

# 查看 Keepalived 状态
sudo systemctl status keepalived

# 查看 VRRP 日志
journalctl -u keepalived -f

# 查看 VIP 绑定情况
ip addr show dev eth0
```

从日志中可以看到主备的交互：

```
Feb 15 10:00:01 master Keepalived_vrrp[1234]: Sending gratuitous ARP on eth0 for 10.0.0.100
Feb 15 10:00:01 master Keepalived_vrrp[1234]: VRRP_Instance(VI_1) Transition to MASTER STATE
```

## 测试故障切换

```bash
# 在主节点上停掉 Nginx
sudo systemctl stop nginx

# 观察日志
journalctl -u keepalived -f

# 检查 VIP 是否漂移到备节点
# 在备节点上执行
ip addr show eth0 | grep 10.0.0.100

# 恢复主节点的 Nginx
sudo systemctl start nginx
```

由于启用了 `nopreempt`，主节点恢复后不会自动抢回 VIP，避免了不必要的切换。

## 双主模式（负载 + 高可用）

两台 Nginx 都干活，互相备份：

```
               VIP1: 10.0.0.100（主 Node1，备 Node2）
用户请求 ────┤
               VIP2: 10.0.0.101（主 Node2，备 Node1）
```

### Node1 配置

```bash
vrrp_instance VI_1 {
    state MASTER
    interface eth0
    virtual_router_id 51
    priority 150
    virtual_ipaddress {
        10.0.0.100/24 dev eth0
    }
}

vrrp_instance VI_2 {
    state BACKUP
    interface eth0
    virtual_router_id 52
    priority 100
    virtual_ipaddress {
        10.0.0.101/24 dev eth0
    }
}
```

### Node2 配置

```bash
vrrp_instance VI_1 {
    state BACKUP
    interface eth0
    virtual_router_id 51
    priority 100
    virtual_ipaddress {
        10.0.0.100/24 dev eth0
    }
}

vrrp_instance VI_2 {
    state MASTER
    interface eth0
    virtual_router_id 52
    priority 150
    virtual_ipaddress {
        10.0.0.101/24 dev eth0
    }
}
```

再配合 DNS 轮询或 SLB，流量均匀分布在两台 Nginx 上，任意一台挂了另一台接管所有流量。

## Nginx 配置同步

主备节点的 Nginx 配置需要保持一致。推荐方案：

### 方案一：版本控制 + 手动同步

```bash
# 用 git 管理配置
cd /etc/nginx
git init
git add .
git commit -m "init nginx config"

# 在备机上 pull
git pull origin main
nginx -t && systemctl reload nginx
```

### 方案二：lsyncd 实时同步

```bash
# 安装 lsyncd
sudo apt install lsyncd

# /etc/lsyncd/lsyncd.conf
settings {
    logfile = "/var/log/lsyncd/lsyncd.log",
    statusFile = "/var/log/lsyncd/lsyncd.status"
}

sync {
    default.rsync,
    source = "/etc/nginx/",
    target = "10.0.0.11:/etc/nginx/",
    exclude = { ".git" }
}
```

### 方案三：配置管理工具

使用 Ansible、SaltStack 等工具统一管理配置。

## DNS 轮询 + Keepalived

对 VIP 配置多个 DNS A 记录，配合 Keepalived：

```
example.com A 10.0.0.100
example.com A 10.0.0.101
example.com A 10.0.0.102
```

每个 IP 背后都是一组 Keepalived 主备对。

## 完整高可用架构

```
                      ┌─ DNS / SLB
                      │
              ┌───────┴────────┐
              │                │
         Nginx 主           Nginx 备
        (10.0.0.10)      (10.0.0.11)
              │                │
              └───────┬────────┘
                      │ VIP: 10.0.0.100
                      │
              ┌───────┴────────┐
              │                │
         App Server 1     App Server 2
         App Server 3     App Server 4
              │                │
              └───────┬────────┘
                      │
                  Database
                 (主从/集群)
```

**故障场景**：

| 故障 | 影响 | 恢复方式 |
|------|------|---------|
| Nginx 主挂了 | VIP 漂移到备机（秒级）| 自动 |
| Nginx 主恢复 | 备机继续服务（nopreempt）| 手动切换或自动 |
| 后端 Server 挂了 | 负载均衡自动摘除 | 自动 |
| 整机宕机 | VIP 漂移 + 后端故障转移 | 自动 |
