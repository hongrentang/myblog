## 为什么需要缓存？

缓存的核心是**用空间换时间**——把处理过的结果存起来，下次直接返回，避免重复计算。

场景对比：

| 场景 | 无缓存 | 有缓存 |
|------|--------|--------|
| 首页加载 | 200ms + 后端渲染 | 5ms 直接返回 |
| 热点文章 | 每次都要查数据库 | 静态 HTML 直接返回 |
| API 响应 | 每次都要执行业务逻辑 | 缓存期直接返回 |

---

## Nginx 缓存体系

Nginx 的缓存分为两个层面：

1. **代理缓存（Proxy Cache）**：在 Nginx 层缓存后端响应
2. **浏览器缓存**：通过响应头控制浏览器本地缓存

---

## 一、代理缓存

### 基础配置

```nginx
# 在 http 块中定义缓存路径
http {
    proxy_cache_path /var/cache/nginx levels=1:2 keys_zone=my_cache:10m
                     max_size=1g inactive=60m use_temp_path=off;

    server {
        location / {
            proxy_pass http://backend;
            proxy_cache my_cache;
            proxy_cache_valid 200 302 10m;
            proxy_cache_valid 404 1m;
            proxy_cache_valid any 1m;
        }
    }
}
```

### 参数说明

| 参数 | 说明 | 示例 |
|------|------|------|
| `levels` | 缓存目录层级 | `1:2` → `/c/29` |
| `keys_zone` | 缓存键的内存区域 | `my_cache:10m`（10MB 约存 80000 个 key） |
| `max_size` | 缓存最大磁盘占用 | `1g` |
| `inactive` | 缓存未被访问后的保留时间 | `60m` |
| `use_temp_path` | 是否使用临时路径 | `off`（直接写入缓存目录）|

### 缓存命中判断

添加响应头来查看缓存状态：

```nginx
add_header X-Cache-Status $upstream_cache_status;
```

可能的返回值：
- `HIT` — 缓存命中
- `MISS` — 缓存未命中
- `EXPIRED` — 缓存过期
- `STALE` — 缓存过期但使用了过期版本
- `BYPASS` — 手动绕过缓存
- `REVALIDATED` — 缓存被远程服务器验证有效

### 缓存键

默认的缓存键由完整 URL 决定：

```nginx
# 查看默认缓存键
proxy_cache_key $scheme$proxy_host$uri$is_args$args;

# 自定义缓存键（例如忽略 query string 里的 timestamp）
proxy_cache_key $scheme$proxy_host$uri;
```

### 缓存绕过与强制刷新

```nginx
location / {
    proxy_pass http://backend;
    proxy_cache my_cache;

    # Cookie 中包含 sessionid 则不缓存
    proxy_no_cache $cookie_sessionid;

    # GET/HEAD 之外不缓存
    proxy_cache_methods GET HEAD;

    # 手动绕过缓存（带上特定参数刷新）
    proxy_cache_bypass $arg_nocache;
    proxy_no_cache $arg_nocache;
}
```

访问 `?nocache=1` 即可绕过缓存获取最新内容。

### 缓存锁定

高并发下多个请求同时未命中缓存，会全部穿透到后端：

```nginx
proxy_cache_lock on;
proxy_cache_lock_timeout 5s;
```

第一个请求去后端取数据，后续请求等待第一个请求的结果。如果 5 秒内没有返回，后续请求穿透。

### 用 Cookie 区分缓存

```nginx
proxy_cache_key $scheme$proxy_host$uri$is_args$args$cookie_user_type;
```

不同用户类型获取不同缓存版本。

### 清除缓存

需要 ngx_cache_purge 模块或手动删除：

```bash
# 查找缓存文件
grep -lr "GET /some-path" /var/cache/nginx

# 直接删除缓存目录
rm -rf /var/cache/nginx/*
```

Nginx Plus 支持通过 `purger` 配置自动清除。

## 二、浏览器缓存

浏览器缓存由 Nginx 通过响应头控制，不需要存储空间，但不可控（用户随时可以清除）。

### Expires 头

```nginx
location ~* \.(jpg|jpeg|png|gif|ico)$ {
    expires 30d;
}

location ~* \.(css|js)$ {
    expires 7d;
}

location ~* \.(html)$ {
    expires 1h;
}

location / {
    expires -1;  # 不缓存
}
```

### Cache-Control 头

`expires` 底层实际上设置的是 `Cache-Control` 和 `Expires` 头。你也可以手动控制：

```nginx
# 静态资源：强缓存
location /static/ {
    add_header Cache-Control "public, max-age=2592000, immutable";
}

# HTML 页面：协商缓存
location / {
    add_header Cache-Control "no-cache";
}

# API：不缓存
location /api/ {
    add_header Cache-Control "no-store, must-revalidate";
}
```

### 常见 Cache-Control 值

| 指令 | 含义 |
|------|------|
| `public` | 任何中间节点都可以缓存 |
| `private` | 仅浏览器可以缓存 |
| `no-cache` | 缓存前必须先确认资源是否更新 |
| `no-store` | 禁止缓存（包括浏览器和代理） |
| `max-age=3600` | 缓存有效期 3600 秒 |
| `immutable` | 资源永不变（配合长 max-age，刷新页面也不发请求） |
| `must-revalidate` | 过期后必须重新验证 |

### ETag 和 Last-Modified

Nginx 默认启用 ETag 和 Last-Modified，浏览器会发送 `If-None-Match` 和 `If-Modified-Since` 请求头，Nginx 根据文件是否变化返回 `304 Not Modified`。

```nginx
# 默认行为，无需显式配置
# etag on;
# if_modified_since exact;
```

## 三、分片缓存（Slice）

对大文件启用分片缓存，支持部分内容更新和断点续传：

```nginx
proxy_cache_path /var/cache/nginx levels=1:2 keys_zone=slice_cache:10m;

server {
    location / {
        proxy_cache slice_cache;
        proxy_cache_key $uri$is_args$args;
        slice 1m;  # 每片 1MB

        proxy_cache_valid 200 206 24h;

        # 设置 range 回源
        proxy_set_header Range $slice_range;
    }
}
```

适用场景：视频流、大文件下载。

## 缓存场景实战

### 场景一：WordPress 站点缓存

```nginx
proxy_cache_path /var/cache/nginx levels=1:2 keys_zone=wp_cache:10m max_size=1g;

server {
    listen 80;
    server_name blog.example.com;

    location / {
        proxy_pass http://php_backend;
        proxy_cache wp_cache;

        # 清除缓存的快捷方式
        proxy_cache_key $scheme$host$uri;

        # 管理员不缓存
        proxy_no_cache $cookie_wordpress_logged_in;
        proxy_cache_bypass $cookie_wordpress_logged_in;

        proxy_cache_valid 200 302 10m;
        proxy_cache_valid 404 1m;
    }

    # 静态资源不经过 PHP，直接让 Nginx 处理
    location ~* \.(css|js|jpg|jpeg|png|gif|ico|woff)$ {
        root /var/www/wordpress;
        expires 30d;
        add_header Cache-Control "public, immutable";
    }
}
```

### 场景二：API 缓存

```nginx
proxy_cache_path /var/cache/nginx levels=1:2 keys_zone=api_cache:50m max_size=2g;

server {
    listen 80;
    server_name api.example.com;

    location / {
        proxy_pass http://api_backend;
        proxy_cache api_cache;

        # 根据请求方法决定是否缓存
        proxy_cache_methods GET HEAD;

        # 按参数缓存
        proxy_cache_key $scheme$host$uri$is_args$args;

        # 根据状态码设置缓存时间
        proxy_cache_valid 200 302 5m;
        proxy_cache_valid 404 1m;
        proxy_cache_valid 500 502 503 0s;  # 错误不缓存

        # 缓存锁定防穿透
        proxy_cache_lock on;
        proxy_cache_lock_timeout 5s;

        add_header X-Cache-Status $upstream_cache_status;
    }
}
```

## 缓存策略决策树

```
请求来了
├─ 资源是静态文件（css/js/img）？
│   ├─ 是 → 浏览器缓存（长 max-age + immutable）
│   └─ 否 → 走代理缓存
├─ 请求需要实时数据？
│   ├─ 是 → 不缓存 或 极短缓存（几秒）
│   └─ 否 → 代理缓存
├─ 资源变化频率？
│   ├─ 从不 → 浏览器缓存 + 代理缓存
│   ├─ 偶尔 → 短时代理缓存 + 浏览器 no-cache
│   └─ 频繁 → 不缓存
```
