## 什么是动静分离？

**动静分离**是指将动态请求（API、页面渲染）和静态资源（CSS、JS、图片、字体）分开处理。

```
静态资源（CSS/JS/IMG）→ Nginx 直接返回（快）
动态请求（API/页面）   → Nginx 代理到后端（处理业务逻辑）
```

**为什么需要动静分离？**

- **减轻后端压力**：静态资源不需要经过应用服务器
- **提升响应速度**：Nginx 处理静态文件比 Tomcat/Node.js 快 10-100 倍
- **缓存友好**：静态资源可以配置长时间缓存
- **CDN 友好**：静态资源可以直接托管到 CDN

## 一、基础动静分离

### 同域名分离

```nginx
server {
    listen 80;
    server_name www.example.com;

    root /var/www/example;

    # 静态资源直接由 Nginx 处理
    location /static/ {
        expires 30d;
        add_header Cache-Control "public, immutable";
    }

    location /uploads/ {
        expires 7d;
        add_header Cache-Control "public";
    }

    # 动态请求代理到后端
    location / {
        proxy_pass http://backend:3000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }
}
```

### 独立域名分离（推荐）

```nginx
# 静态资源域名
server {
    listen 80;
    server_name static.example.com;

    root /var/www/static;
    index index.html;

    location / {
        expires 30d;
        add_header Cache-Control "public, immutable";
        add_header Access-Control-Allow-Origin "*";  # 允许跨域

        # 文件 hash 版本控制
        location ~* \.(\w+)\.(css|js)$ {
            # 对带 hash 的文件做更激进的缓存
            expires 365d;
            add_header Cache-Control "public, immutable";
        }
    }

    # 图片压缩/缩放（需要 image_filter 模块）
    location /images/ {
        image_filter resize 800 600;
        image_filter_jpeg_quality 85;
    }
}

# 动态内容域名
server {
    listen 80;
    server_name api.example.com;

    location / {
        proxy_pass http://backend:3000;
        proxy_set_header Host $host;
    }
}

# 前端页面域名
server {
    listen 80;
    server_name www.example.com;

    location / {
        proxy_pass http://frontend:3000;
        proxy_set_header Host $host;
    }
}
```

静态资源使用独立域名（`static.example.com`）的好处：
- 浏览器对同一域名的并发连接数有限制（通常 6-8 个）
- 跨域独立后，静态资源可以和页面并行加载
- 便于迁移到 CDN

## 二、版本控制与缓存策略

### 文件 hash 策略

前端构建工具（Webpack/Vite）通常会在文件名中加入内容 hash：

```nginx
location ~* \.[a-f0-9]{8}\.(css|js)$ {
    # hash 文件：内容变了文件名才变，可以永久缓存
    expires 365d;
    add_header Cache-Control "public, immutable";
}

location ~* \.(css|js)$ {
    # 非 hash 文件：短时间缓存
    expires 7d;
    add_header Cache-Control "public";
}
```

### 版本号策略

手动版本号参数：

```nginx
# HTML 中引用时带版本号
# <link rel="stylesheet" href="/static/css/main.css?v=2.3.1">
```

Nginx 端不需要特殊处理，浏览器会自动根据 URL 变化重新请求。

## 三、CDN 融合

### Nginx 回源到 CDN

```nginx
upstream cdn_origin {
    server origin-cdn.example.com:443;
    keepalive 32;
}

server {
    listen 80;
    server_name static.example.com;

    # 本地缓存层（L1 cache）
    proxy_cache_path /var/cache/nginx/cdn levels=1:2 keys_zone=cdn_cache:1g max_size=10g;

    location / {
        proxy_pass https://cdn_origin;
        proxy_cache cdn_cache;
        proxy_cache_valid 200 7d;
        proxy_cache_use_stale error timeout updating;

        # 缓存锁定
        proxy_cache_lock on;
        proxy_cache_lock_timeout 5s;

        # 缓存状态
        add_header X-Cache-Status $upstream_cache_status;
    }
}
```

### Nginx 作为源站 CDN 回源

```nginx
server {
    listen 80;
    server_name origin.example.com;

    # 仅允许 CDN 节点 IP 访问
    allow 103.21.244.0/22;   # Cloudflare IP 示例
    allow 103.22.200.0/22;
    deny all;

    root /var/www/static;

    location / {
        expires 30d;
        add_header Cache-Control "public";
    }
}
```

## 四、图片处理

### 使用 image_filter 模块

```nginx
location /uploads/ {
    # 生成缩略图
    location ~* /thumbnails/(.+)\.jpg$ {
        alias /var/www/uploads/$1.jpg;
        image_filter resize 200 150;
        image_filter_jpeg_quality 85;
    }

    # 限制图片尺寸
    location ~* \.(jpg|png)$ {
        image_filter resize 1920 1080;
        image_filter_jpeg_quality 90;
    }
}
```

**注意**：`image_filter` 模块需要编译时添加 `--with-http_image_filter_module`。

### 图片防盗链

```nginx
location ~* \.(jpg|jpeg|png|gif|webp|bmp)$ {
    valid_referers none blocked
        ~\.example\.com
        ~\.google\.com
        ~.*\.example\.com;

    if ($invalid_referer) {
        return 403;
    }

    expires 30d;
    add_header Cache-Control "public";
}

# 使用透明图片代替 403（更好的用户体验）
location ~* \.(jpg|jpeg|png|gif)$ {
    valid_referers none blocked server_names ~\.example\.com;

    if ($invalid_referer) {
        rewrite ^ /images/forbidden.png break;
    }
}
```

## 五、多版本部署

静态资源多版本并存，实现灰度发布：

```nginx
server {
    listen 80;
    server_name static.example.com;

    root /var/www/static;

    # 默认版本
    location / {
        root /var/www/static/v2;
    }

    # A/B 测试：根据 Cookie 切换版本
    location / {
        if ($cookie_version = "v1") {
            root /var/www/static/v1;
        }
        root /var/www/static/v2;
    }

    # 根据 User-Agent 降级（针对旧浏览器）
    location / {
        if ($http_user_agent ~* "MSIE 8|MSIE 7") {
            root /var/www/static/legacy;
        }
    }
}
```

## 六、动静分离完整架构示例

### Nginx 配置

```nginx
# 上游后端
upstream api {
    least_conn;
    keepalive 32;
    server 10.0.0.1:8080;
    server 10.0.0.2:8080;
}

upstream ssr {
    server 10.0.0.3:3000;
    server 10.0.0.4:3000;
}

# 页面和 API
server {
    listen 443 ssl http2;
    server_name www.example.com;

    # 页面请求（SSR）
    location / {
        proxy_pass http://ssr;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    # API 请求
    location /api/ {
        proxy_pass http://api/;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;

        # API 不做缓存
        proxy_no_cache 1;
        proxy_cache_bypass 1;
    }

    # WebSocket
    location /ws {
        proxy_pass http://ssr;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
    }
}

# 静态资源
server {
    listen 443 ssl http2;
    server_name static.example.com;

    root /var/www/static;

    location / {
        expires 30d;
        add_header Cache-Control "public, immutable";
        add_header Access-Control-Allow-Origin "*";

        # 文件 hash 版本：永久缓存
        location ~* \.[a-f0-9]{8,}\.(css|js|jpg|png)$ {
            expires 365d;
            add_header Cache-Control "public, immutable";
        }

        # 非 hash 文件：短缓存
        location ~* \.(css|js)$ {
            expires 7d;
            add_header Cache-Control "public";
        }
    }

    # gzip 预压缩
    location ~* \.(css|js)$ {
        gzip_static on;  # 使用预生成的 .gz 文件
        expires 30d;
    }

    # 图片处理
    location /images/ {
        image_filter resize 1200 900;
        image_filter_jpeg_quality 85;
    }
}

# HTTP 跳转 HTTPS
server {
    listen 80;
    server_name example.com www.example.com static.example.com;
    return 301 https://$server_name$request_uri;
}
```

### 前端构建产物部署建议

```
/var/www/static/
├── v1.0.0/
│   ├── css/
│   │   ├── main.a1b2c3d4.css    # hash 命名
│   │   └── vendor.e5f6g7h8.css
│   ├── js/
│   │   ├── main.x1y2z3u4.js
│   │   └── vendor.v1w2x3y4.js
│   └── images/
├── v1.1.0/
└── current -> v1.1.0/           # 软链接，回滚只需 ln -snf
```

## 七、SSR + 静态资源分离

现代前端框架（Next.js/Nuxt）的服务端渲染架构：

```
用户请求
    ↓
Nginx（判断路径）
    ├─ /static/* 或 /_next/* → 直接返回静态文件（高性能）
    └─ 其他路径 → 代理到 SSR Server
                        ↓
                SSR Server（Node.js）
                        ↓
                返回渲染好的 HTML
```

```nginx
# Next.js 动静分离
server {
    listen 80;
    server_name example.com;

    # Next.js 构建产物（hash 文件名，永久缓存）
    location /_next/static/ {
        root /var/www/next;
        expires 365d;
        add_header Cache-Control "public, immutable";
    }

    # 公共静态资源
    location /static/ {
        root /var/www/next/public;
        expires 30d;
    }

    # 其他请求走 SSR
    location / {
        proxy_pass http://nextjs:3000;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }
}
```
