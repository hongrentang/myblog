## 什么是反向代理？

**正向代理**：代理客户端，帮助客户端访问它无法直接访问的资源（如翻墙、公司内网代理）。

**反向代理**：代理服务器，客户端不知道请求最终由哪台后端服务器处理。

```
客户端 → Nginx（反向代理）→ 后端服务器（Tomcat/Node.js/Python...）
```

反向代理的典型用途：

- 隐藏后端服务器真实地址
- 统一入口（一个域名对应多个后端服务）
- 负载均衡
- SSL 终结（证书统一放在 Nginx 层）
- 缓存和静态资源分离

---

## 最简单的反向代理

```nginx
server {
    listen 80;
    server_name api.example.com;

    location / {
        proxy_pass http://127.0.0.1:8080;
    }
}
```

所有访问 `api.example.com` 的请求都会被转发到本机的 `8080` 端口。

## proxy_pass 语法细节

### 带 URI vs 不带 URI

```nginx
# 不带 URI：将完整 URI 原样转发
location /api {
    proxy_pass http://backend;  
    # 请求 /api/users → http://backend/api/users
}

# 带 URI（有 / 路径）：匹配部分被替换
location /api {
    proxy_pass http://backend/;
    # 请求 /api/users → http://backend/users
}

location /api {
    proxy_pass http://backend/v2/;
    # 请求 /api/users → http://backend/v2/users
}
```

**这是最容易踩坑的地方。** 记住一条规则：

> `proxy_pass` 后面有没有 `/`，决定了 location 匹配的部分是否被替换。

## 标准反向代理配置

```nginx
location / {
    proxy_pass http://backend;

    # 设置请求头
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;

    # 禁用默认头（某些环境下需要）
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection "upgrade";

    # 超时设置
    proxy_connect_timeout 30s;
    proxy_read_timeout 60s;
    proxy_send_timeout 60s;

    # 缓冲
    proxy_buffering on;
    proxy_buffer_size 4k;
    proxy_buffers 8 4k;
    proxy_busy_buffers_size 8k;

    # 请求体大小限制
    client_max_body_size 10m;
}
```

### 各配置说明

| 配置项 | 说明 | 默认值 |
|--------|------|--------|
| `proxy_set_header` | 修改转发请求头 | 见下 |
| `proxy_connect_timeout` | 连接后端超时 | 60s |
| `proxy_read_timeout` | 读取后端响应超时 | 60s |
| `proxy_send_timeout` | 发送数据到后端超时 | 60s |
| `proxy_buffering` | 是否开启缓冲 | on |
| `client_max_body_size` | 客户端请求体上限 | 1m |

`Host` 头的默认值是 `$proxy_host`（后端地址），通常需要改成 `$host` 让后端知道原始域名。

## 代理不同路径到不同后端

```nginx
server {
    listen 80;
    server_name example.com;

    # API 请求转发到 Java 后端
    location /api/ {
        proxy_pass http://java_backend:8080/;
        proxy_set_header Host $host;
    }

    # 用户中心转发到 Python 后端
    location /user/ {
        proxy_pass http://python_backend:5000/;
        proxy_set_header Host $host;
    }

    # WebSocket 转发
    location /ws/ {
        proxy_pass http://websocket_server:3000;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
    }

    # 静态文件直接由 Nginx 处理
    location /static/ {
        root /var/www;
        expires 7d;
    }
}
```

## WebSocket 代理

WebSocket 需要显式支持 Upgrade 头：

```nginx
location /ws {
    proxy_pass http://ws_backend;

    proxy_http_version 1.1;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection "upgrade";
    proxy_set_header Host $host;

    # WebSocket 长连接需要更长的超时
    proxy_read_timeout 3600s;
    proxy_send_timeout 3600s;
}
```

关键点：
- `proxy_http_version 1.1`：WebSocket 需要 HTTP/1.1
- `Upgrade` 和 `Connection` 头必须透传
- 超时时间要设长，否则连接会被断开

## 上游服务器组（upstream）

当后端有多个实例时，用 `upstream` 定义一组服务器：

```nginx
upstream backend {
    server 10.0.0.1:8080 weight=3;
    server 10.0.0.2:8080 weight=2;
    server 10.0.0.3:8080 backup;     # 备机

    keepalive 32;                      # 保持长连接
}

server {
    listen 80;
    location / {
        proxy_pass http://backend;
        proxy_http_version 1.1;
        proxy_set_header Connection "";
    }
}
```

`upstream` 是负载均衡的基础。

## 选择后端协议

```nginx
# HTTP
proxy_pass http://backend;

# HTTPS
proxy_pass https://backend;

# Unix Socket（性能更好）
proxy_pass http://unix:/tmp/backend.sock;

# FastCGI（用于 PHP）
fastcgi_pass unix:/var/run/php/php8.3-fpm.sock;
```

对于本地通信，Unix Socket 比 TCP 更高效，适合 PHP-FPM 等场景。

## 常见问题排查

### 502 Bad Gateway

后端服务没有启动或端口不对。

```bash
# 检查后端是否存活
curl http://127.0.0.1:8080

# 查看 Nginx 错误日志
tail -f /var/log/nginx/error.log
```

### 504 Gateway Timeout

后端处理时间太长，Nginx 在 `proxy_read_timeout` 内没收到响应。

```nginx
# 对慢接口增加超时
location /slow-api {
    proxy_pass http://backend;
    proxy_read_timeout 300s;
}
```

### 404 错误

通常是 `proxy_pass` 的 URI 路径不匹配，检查是否有 `trailing slash`。

### 请求头丢失

检查 `proxy_set_header` 是否配置正确，特别是 `Host` 和 `X-Forwarded-*` 系列头。

## 获取真实客户端 IP

经过反向代理后，后端看到的 IP 是 Nginx 的 IP。转发真实 IP 需要：

```nginx
proxy_set_header X-Real-IP $remote_addr;
proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
proxy_set_header X-Forwarded-Proto $scheme;
```

后端代码获取：

```python
# Python
real_ip = request.headers.get('X-Real-IP') or request.headers.get('X-Forwarded-For')

# Java
String realIp = request.getHeader("X-Real-IP");
```
