## 备份的重要性

```
没备份之前：人分两种，没出过事的和已经出事了的
有备份之后：人分两种，能恢复的和不能恢复的
```

一个没有备份的生产数据库，距离灾难只有一次误操作的距离。

**你知道该怎么做：**

- 定期备份（全量 + binlog）
- 定期验证备份（备份文件能否成功恢复）
- 异地存储（备份不要和数据库放在同一台机器）

---

## 一、备份类型

| 类型 | 说明 | 速度 | 恢复速度 | 存储 |
|------|------|------|---------|------|
| **逻辑备份** | SQL 语句形式（mysqldump）| 慢 | 慢 | 可压缩，体积小 |
| **物理备份** | 直接拷贝数据文件 | 快 | 快 | 不可压缩，体积大 |

| 方式 | 说明 | 使用场景 |
|------|------|---------|
| **全量备份** | 备份全部数据 | 定期（如每天凌晨）|
| **增量备份** | 备份上次备份后变化的数据 | 频繁变更的系统 |
| **binlog 备份** | 备份二进制日志 | 实现时间点恢复 |

## 二、mysqldump 逻辑备份

### 基本用法

```bash
# 备份单个数据库
mysqldump -u root -p shop > shop_backup.sql

# 备份多个数据库
mysqldump -u root -p --databases shop blog > multi_backup.sql

# 备份所有数据库
mysqldump -u root -p --all-databases > all_backup.sql

# 备份单张表
mysqldump -u root -p shop users > users_backup.sql
```

### 常用参数

```bash
# 包含存储过程和事件（默认不包含）
mysqldump -u root -p --routines --events shop > backup.sql

# 只备份表结构
mysqldump -u root -p --no-data shop > schema.sql

# 只备份数据（不包含建表语句）
mysqldump -u root -p --no-create-info shop > data.sql

# 压缩备份（推荐）
mysqldump -u root -p shop | gzip > shop_$(date +%Y%m%d).sql.gz

# 指定字符集
mysqldump -u root -p --default-character-set=utf8mb4 shop > backup.sql
```

### 生产环境推荐参数

```bash
mysqldump -u root -p \
  --single-transaction \       # 不加锁备份（使用 InnoDB 事务）
  --routines \                 # 包含存储过程
  --events \                   # 包含事件
  --triggers \                 # 包含触发器
  --master-data=2 \            # 记录 binlog 位置（用于主从搭建）
  --set-gtid-purged=ON \       # GTID 信息
  --skip-lock-tables \         # 不锁表（配合 single-transaction）
  --quick \                    # 逐行读取，避免内存过大
  shop | gzip > shop_$(date +%Y%m%d_%H%M%S).sql.gz
```

> **`--single-transaction`** 是 InnoDB 的关键参数——它在事务开始时创建一个一致性快照，备份期间其他事务的 DML 不会影响备份内容，且不需要锁表（MyISAM 仍然需要锁表，启动参数前确认你的表都是 InnoDB）。

## 三、备份恢复

```bash
# 恢复完整备份
mysql -u root -p shop < shop_backup.sql

# 从压缩文件恢复
gunzip < shop_20250115.sql.gz | mysql -u root -p shop

# 恢复多个数据库
mysql -u root -p < multi_backup.sql

# 恢复所有数据库
mysql -u root -p < all_backup.sql
```

### 部分恢复

```bash
# 从全量备份中恢复单张表
sed -n '/^-- Table structure for table `users`/,/^-- Table structure for table/p' backup.sql > users.sql
mysql -u root -p shop < users.sql

# 更精准的方法：用正则提取
# 使用 mysqldump 时通过参数过滤表
mysqldump -u root -p shop users orders > partial.sql
```

## 四、物理备份

### XtraBackup（推荐）

Percona XtraBackup 支持 InnoDB 的**热备**，不阻塞读写。

```bash
# 安装
sudo apt install percona-xtrabackup-84

# 全量备份
xtrabackup --backup \
  --user=root \
  --password=xxx \
  --target-dir=/backups/full/

# 准备备份（应用 redo log，使数据一致）
xtrabackup --prepare --target-dir=/backups/full/

# 恢复
systemctl stop mysql
rm -rf /var/lib/mysql/*
xtrabackup --copy-back --target-dir=/backups/full/
chown -R mysql:mysql /var/lib/mysql
systemctl start mysql

# 增量备份
xtrabackup --backup \
  --target-dir=/backups/inc1 \
  --incremental-basedir=/backups/full/

# 合并增量到全量
xtrabackup --prepare \
  --apply-log-only \
  --target-dir=/backups/full/
xtrabackup --prepare \
  --target-dir=/backups/full/ \
  --incremental-dir=/backups/inc1/
```

### 文件直接拷贝

```bash
# 停 MySQL 后直接拷贝数据目录（冷备）
systemctl stop mysql
cp -r /var/lib/mysql /backups/mysql_cold_$(date +%Y%m%d)
systemctl start mysql
```

## 五、binlog 与时间点恢复

binlog（二进制日志）记录了所有数据变更操作，是**增量恢复**的关键。

### 启用 binlog

```ini
# my.cnf
[mysqld]
server-id = 1
log_bin = /var/log/mysql/mysql-bin.log
binlog_format = ROW          # 推荐 ROW 格式
expire_logs_days = 7         # 保留 7 天
binlog_row_image = FULL      # 记录全部列（便于恢复）
```

### 查看 binlog

```bash
# 查看所有 binlog 文件
mysql -u root -p -e "SHOW BINARY LOGS;"

# 查看当前正在写的 binlog
mysql -u root -p -e "SHOW MASTER STATUS;"

# 查看 binlog 内容
mysqlbinlog /var/log/mysql/mysql-bin.000023 > binlog.sql

# 按时间查看
mysqlbinlog \
  --start-datetime="2025-01-15 10:00:00" \
  --stop-datetime="2025-01-15 11:00:00" \
  /var/log/mysql/mysql-bin.000023 > recover.sql
```

### 完整恢复流程

**场景**：用户在 10:30 误 DELETE 了一张表。

```bash
# 1. 恢复最近的完整备份
mysql -u root -p shop < shop_20250115.sql

# 2. 回放备份之后的 binlog（跳过误操作的时间点）
mysqlbinlog \
  --start-datetime="2025-01-15 03:00:00" \
  --stop-datetime="2025-01-15 10:29:59" \
  /var/log/mysql/mysql-bin.* | mysql -u root -p shop

# 或者在日志中找到误操作的日志位置，用位置恢复
mysqlbinlog \
  --start-position=12345 \
  --stop-position=67890 \
  /var/log/mysql/mysql-bin.* | mysql -u root -p shop
```

### 指定位置恢复

```bash
# 查看 binlog 找到误操作位置
mysqlbinlog /var/log/mysql/mysql-bin.000023 | grep -n "DROP TABLE\|DELETE FROM users"

# 按位置恢复
mysqlbinlog \
  --stop-position=12345 \   # 停在误操作之前
  /var/log/mysql/mysql-bin.000023 | mysql -u root -p shop

# 如果已被踩掉一个位置，跳过后继续
mysqlbinlog \
  --start-position=67890 \   # 从误操作之后开始
  /var/log/mysql/mysql-bin.000023 | mysql -u root -p shop
```

## 六、自动化备份脚本

```bash
#!/bin/bash
# /usr/local/bin/mysql_backup.sh

DB_USER="root"
DB_PASS="your_password"
DB_NAME="shop"
BACKUP_DIR="/backups/mysql"
DATE=$(date +%Y%m%d_%H%M%S)
RETENTION_DAYS=30

# 创建备份目录
mkdir -p "$BACKUP_DIR"

# mysqldump 备份
echo "[$(date)] Starting backup of $DB_NAME..."
mysqldump \
  --user="$DB_USER" \
  --password="$DB_PASS" \
  --single-transaction \
  --routines \
  --events \
  --triggers \
  --master-data=2 \
  "$DB_NAME" | gzip > "$BACKUP_DIR/${DB_NAME}_${DATE}.sql.gz"

# 检查备份是否成功
if [ $? -eq 0 ] && [ -s "$BACKUP_DIR/${DB_NAME}_${DATE}.sql.gz" ]; then
    echo "[$(date)] Backup completed: ${BACKUP_DIR}/${DB_NAME}_${DATE}.sql.gz"
else
    echo "[$(date)] Backup FAILED!"
    exit 1
fi

# 删除旧备份
find "$BACKUP_DIR" -name "${DB_NAME}_*.sql.gz" -mtime +$RETENTION_DAYS -delete

# 同步到异地（可选）
# rsync -avz "$BACKUP_DIR/" user@remote-server:/backups/mysql/
```

**配合 crontab 使用**：

```bash
# 每天凌晨 3:00 备份
0 3 * * * /usr/local/bin/mysql_backup.sh
```

## 七、备份验证

> 备份不做恢复验证 = 没有备份

```bash
#!/bin/bash
# 定期验证备份

BACKUP_FILE="/backups/mysql/shop_20250115.sql.gz"
TEST_DB="restore_test"

# 创建测试数据库
mysql -u root -p -e "CREATE DATABASE IF NOT EXISTS $TEST_DB"

# 恢复备份到测试库
gunzip < "$BACKUP_FILE" | mysql -u root -p $TEST_DB

# 检查是否正常
ERROR_COUNT=$(mysql -u root -p $TEST_DB -e "SHOW TABLE STATUS" 2>&1 | grep -c "Error")

if [ "$ERROR_COUNT" -eq 0 ]; then
    echo "[$(date)] Backup verification PASSED"
else
    echo "[$(date)] Backup verification FAILED: $ERROR_COUNT errors"
fi

# 清理
mysql -u root -p -e "DROP DATABASE $TEST_DB"
```

## 八、最佳实践总结

```
备份黄金法则：
┌────────────────────────────────────────────┐
│ 1. 定期全量备份（至少每天）                  │
│ 2. 开启 binlog（实现任意时间点恢复）         │
│ 3. 备份与数据库分离存储                      │
│ 4. 定期验证备份有效性                        │
│ 5. 异地保存一份备份                          │
│ 6. 演练恢复流程（不要等真出事才试）          │
└────────────────────────────────────────────┘
```

| 备份策略 | 使用场景 | RPO（数据丢失量）| RTO（恢复时间）|
|---------|---------|----------------|--------------|
| 每天全量备份 | 小数据量 | 最多丢失 1 天数据 | 几小时 |
| 每天全量 + binlog | 生产系统 | 最多丢失几秒数据 | 几小时 |
| XtraBackup 全量 + 增量 | 大数据量 | 取决于增量频率 | 几十分钟 |
