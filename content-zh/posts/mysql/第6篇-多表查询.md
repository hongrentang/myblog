## 为什么需要多表查询？

真实业务中数据不会全放在一张表里——那样会导致大量冗余和维护困难。通过**外键**关联，将数据拆分到多个表中，查询时再通过 **JOIN** 把它们组合起来。

```
users（用户表）        orders（订单表）          products（商品表）
┌─────────────┐      ┌──────────────────┐      ┌──────────────┐
│ id          │←──┐  │ id               │      │ id           │
│ name        │   └──│ user_id          │      │ name         │
│ email       │      │ product_id       │──→   │ price        │
│ created_at  │      │ quantity         │      │ stock        │
└─────────────┘      │ total_amount     │      └──────────────┘
                     │ created_at       │
                     └──────────────────┘
```

## 一、JOIN 类型总览

```sql
-- 准备示例数据
CREATE TABLE departments (
    id INT PRIMARY KEY,
    name VARCHAR(50)
);

CREATE TABLE employees (
    id INT PRIMARY KEY,
    name VARCHAR(50),
    dept_id INT
);

INSERT INTO departments VALUES (1, '技术部'), (2, '市场部'), (3, '财务部'), (4, '运维部');
INSERT INTO employees VALUES (1, '张三', 1), (2, '李四', 1), (3, '王五', 2), (4, '赵六', NULL);
```

### INNER JOIN（内连接）

只返回两表中匹配的行：

```sql
SELECT e.name, d.name AS dept
FROM employees e
INNER JOIN departments d ON e.dept_id = d.id;

-- 结果：张三 技术部, 李四 技术部, 王五 市场部
-- 赵六 没有部门，不返回。运维部 没有员工，不返回。
```

### LEFT JOIN（左连接）

返回左表所有行，右表匹配不到则为 NULL：

```sql
SELECT e.name, d.name AS dept
FROM employees e
LEFT JOIN departments d ON e.dept_id = d.id;

-- 结果：张三 技术部, 李四 技术部, 王五 市场部, 赵六 NULL
```

### RIGHT JOIN（右连接）

返回右表所有行，左表匹配不到则为 NULL：

```sql
SELECT e.name, d.name AS dept
FROM employees e
RIGHT JOIN departments d ON e.dept_id = d.id;

-- 结果：张三 技术部, 李四 技术部, 王五 市场部, NULL 运维部
```

### 记忆方法

```
INNER JOIN = 两圆交集
LEFT JOIN  = 左圆全部 + 交集
RIGHT JOIN = 右圆全部 + 交集
FULL JOIN  = 两圆的并集（MySQL 不支持，用 UNION 模拟）
```

## 二、多表 JOIN 实战

### 三表关联

```sql
-- 查询订单信息（含用户和商品）
SELECT
    o.id AS order_id,
    u.name AS user_name,
    p.name AS product_name,
    o.quantity,
    o.total_amount,
    o.created_at
FROM orders o
JOIN users u ON o.user_id = u.id
JOIN products p ON o.product_id = p.id;
```

### 自连接

同一张表自己关联自己：

```sql
-- 员工与上级（假设表中有 manager_id 字段）
SELECT
    e.name AS employee,
    m.name AS manager
FROM employees e
LEFT JOIN employees m ON e.manager_id = m.id;

-- 查询连续日期
SELECT a.date AS start_date, b.date AS end_date
FROM sales a
JOIN sales b ON DATEDIFF(b.date, a.date) = 1;
```

### 条件 JOIN

```sql
-- 只关联 VIP 用户的订单
SELECT u.name, o.total_amount
FROM users u
LEFT JOIN orders o ON o.user_id = u.id AND o.status = 1
WHERE u.level = 'vip';
```

将条件放在 `ON` 里（不改变行数）而不是 `WHERE` 里（会过滤行）。

## 三、子查询

子查询就是嵌套在另一个 SQL 里的查询。

### WHERE 中的子查询

```sql
-- 查询价格高于平均价的商品
SELECT * FROM products
WHERE price > (SELECT AVG(price) FROM products);

-- 查询有订单的用户（IN）
SELECT * FROM users
WHERE id IN (SELECT DISTINCT user_id FROM orders);

-- 查询没有订单的用户（NOT IN，注意 NULL 问题）
SELECT * FROM users
WHERE id NOT IN (SELECT user_id FROM orders WHERE user_id IS NOT NULL);
```

### FROM 中的子查询（派生表）

```sql
-- 查询每个分类下价格最高的商品
SELECT *
FROM products p
JOIN (
    SELECT category_id, MAX(price) AS max_price
    FROM products
    GROUP BY category_id
) t ON p.category_id = t.category_id AND p.price = t.max_price;
```

### SELECT 中的子查询（标量子查询）

```sql
SELECT
    u.name,
    (SELECT COUNT(*) FROM orders o WHERE o.user_id = u.id) AS order_count,
    (SELECT SUM(total_amount) FROM orders o WHERE o.user_id = u.id AND o.status = 1) AS total_spent
FROM users u
WHERE u.status = 1;
```

## 四、EXISTS vs IN

```sql
-- IN
SELECT * FROM users
WHERE id IN (SELECT user_id FROM orders);

-- EXISTS
SELECT * FROM users u
WHERE EXISTS (SELECT 1 FROM orders o WHERE o.user_id = u.id);
```

| 场景 | 推荐 |
|------|------|
| 子查询结果集很小 | IN |
| 外层表很小，子查询很大 | EXISTS |
| 需要关联外层表 | EXISTS |
| 判断 NULL | EXISTS（IN 遇到 NULL 会有问题） |

## 五、UNION 与 UNION ALL

合并多个查询结果：

```sql
-- UNION（去重）
SELECT name, email FROM vip_users
UNION
SELECT name, email FROM regular_users;

-- UNION ALL（不去重，更快）
SELECT name, email FROM users WHERE city = '北京'
UNION ALL
SELECT name, email FROM users WHERE city = '上海';
```

**规则：**
- 每个 SELECT 的列数必须相同
- 对应列的数据类型必须兼容
- `UNION` 会去重（多一步排序），`UNION ALL` 不会
- 能用 `UNION ALL` 就别用 `UNION`

## 六、笛卡尔积

```sql
-- ❌ 忘记关联条件 → 笛卡尔积（灾难！）
SELECT * FROM employees, departments;
-- 5 个员工 × 4 个部门 = 20 行

-- ✅ 正确的隐式连接
SELECT * FROM employees e, departments d
WHERE e.dept_id = d.id;
```

## 七、复杂查询示例

### 排行榜

```sql
-- 每个分类下销售额 top 3 的商品
SELECT category_id, product_id, total_sales
FROM (
    SELECT
        p.category_id,
        p.id AS product_id,
        SUM(o.quantity * o.price) AS total_sales,
        ROW_NUMBER() OVER (PARTITION BY p.category_id ORDER BY SUM(o.quantity * o.price) DESC) AS rn
    FROM products p
    JOIN order_items o ON p.id = o.product_id
    GROUP BY p.category_id, p.id
) t
WHERE rn <= 3;
```

### 递归查询（CTE，8.0+）

```sql
-- 查询组织架构树
WITH RECURSIVE org_tree AS (
    -- 根节点
    SELECT id, name, parent_id, 1 AS level
    FROM org_units
    WHERE parent_id IS NULL

    UNION ALL

    -- 递归子节点
    SELECT u.id, u.name, u.parent_id, t.level + 1
    FROM org_units u
    JOIN org_tree t ON u.parent_id = t.id
)
SELECT * FROM org_tree ORDER BY level, id;
```

### 统计占比

```sql
SELECT
    u.name,
    COUNT(o.id) AS order_count,
    COUNT(o.id) * 100.0 / SUM(COUNT(o.id)) OVER() AS percentage
FROM users u
LEFT JOIN orders o ON o.user_id = u.id
GROUP BY u.id, u.name
ORDER BY order_count DESC;
```

## 八、JOIN vs 子查询 对比

| 对比项 | JOIN | 子查询 |
|--------|------|--------|
| 可读性 | 好，尤其是多表 | 嵌套深时难读 |
| 性能 | 通常更优（优化器处理） | 依赖具体场景 |
| 灵活性 | 可返回多列 | 标量子查询只能返回一列 |
| 递归 | ❌ | CTE 支持递归 |

**经验法则**：能用 JOIN 解决的场景优先用 JOIN。
