## 一、数值类型

### 整数类型

| 类型 | 占用字节 | 范围（有符号）| 范围（无符号）|
|------|---------|-------------|-------------|
| `TINYINT` | 1 | -128 ~ 127 | 0 ~ 255 |
| `SMALLINT` | 2 | -32768 ~ 32767 | 0 ~ 65535 |
| `MEDIUMINT` | 3 | -8388608 ~ 8388607 | 0 ~ 16777215 |
| `INT` | 4 | -2^31 ~ 2^31-1 | 0 ~ 2^32-1 |
| `BIGINT` | 8 | -2^63 ~ 2^63-1 | 0 ~ 2^64-1 |

```sql
-- 无符号示例
age TINYINT UNSIGNED DEFAULT 0         -- age &gt;= 0

-- 布尔值通常用 TINYINT(1)
is_active TINYINT(1) NOT NULL DEFAULT 1

-- 主键推荐 BIGINT UNSIGNED AUTO_INCREMENT
id BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY
```

### 浮点与定点

| 类型 | 说明 | 使用场景 |
|------|------|---------|
| `FLOAT` | 4 字节，约 7 位精度 | 科学计算，容忍误差 |
| `DOUBLE` | 8 字节，约 15 位精度 | 科学计算 |
| `DECIMAL(M,D)` | 精确小数 | **金额、价格** |

```sql
price DECIMAL(10,2) NOT NULL  -- 总 10 位，小数 2 位，范围 0 ~ 99999999.99

-- ❌ 不要用 FLOAT/DOUBLE 存金额
price FLOAT  -- 可能存为 9.99，读出来成 9.990000000000002
```

**关键规则**：涉及金额、账务等场景**必须**使用 `DECIMAL`。

## 二、字符串类型

| 类型 | 说明 | 最大长度 | 特点 |
|------|------|---------|------|
| `CHAR(M)` | 定长字符串 | 255 字符 | 固定长度，速度快，适合固定长度字段 |
| `VARCHAR(M)` | 变长字符串 | 65535 字节 ≈ 16383 UTF-8 字符 | 灵活，占实际长度 + 1~2 字节 |
| `TINYTEXT` | 短文本 | 255 字节 | — |
| `TEXT` | 长文本 | 65535 字节 | — |
| `MEDIUMTEXT` | 中等文本 | 16MB | — |
| `LONGTEXT` | 超长文本 | 4GB | — |
| `BLOB` | 二进制数据 | 与 TEXT 类似 | 图片、文件等 |

### CHAR vs VARCHAR

```sql
-- CHAR：定长，不足用空格填充
code CHAR(6)  -- 存 'ABC' 实际占用 6 字节

-- VARCHAR：变长，额外开销 1~2 字节
name VARCHAR(50)  -- 存 'ABC' 实际占用 3 + 1 = 4 字节
```

| 场景 | 推荐类型 |
|------|---------|
| 固定编码（手机号、邮编）| `CHAR` |
| 可变长度（名称、标题、地址）| `VARCHAR` |
| 简短唯一码（订单号、身份证号）| `CHAR` |
| 大段文本（文章、描述）| `TEXT` |

### VARCHAR 长度选择

MySQL 对 VARCHAR 的索引长度有限制（InnoDB 最大 767 字节）：

```sql
-- 如果要给 VARCHAR 字段加索引，注意长度
name VARCHAR(255)   -- 索引前缀需要 255 × 3 = 765 字节，接近上限
name VARCHAR(100)   -- 更推荐
```

**经验做法**：
- 名称类：`VARCHAR(50)` ~ `VARCHAR(100)`
- 邮箱：`VARCHAR(100)`
- 手机号：`CHAR(11)`
- URL：`VARCHAR(500)`
- 不确定长度的：`VARCHAR(255)` 是常见上限

## 三、日期时间类型

| 类型 | 占用 | 范围 | 精度 | 建议 |
|------|------|------|------|------|
| `DATE` | 3 字节 | 1000-01-01 ~ 9999-12-31 | 日 | 生日、日期 |
| `DATETIME` | 5 字节 | 同上 | 秒/微秒 | **最常用** |
| `TIMESTAMP` | 4 字节 | 1970-01-01 ~ 2038-01-19 | 秒/微秒 | 依赖时区 |
| `TIME` | 3 字节 | -838:59:59 ~ 838:59:59 | 秒/微秒 | 时间段 |
| `YEAR` | 1 字节 | 1901 ~ 2155 | 年 | 年份 |

### DATETIME vs TIMESTAMP

```sql
-- DATETIME：与时区无关，范围大
created_at DATETIME DEFAULT CURRENT_TIMESTAMP

-- TIMESTAMP：自动转为 UTC 存储，查询时转为当前时区
updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP
```

| 对比 | DATETIME | TIMESTAMP |
|------|----------|-----------|
| 存储空间 | 5 字节 | 4 字节 |
| 时区 | 不感知 | 受时区影响 |
| 范围 | 1000 ~ 9999 | 1970 ~ 2038 |
| 索引效率 | 较好 | 较好 |

**建议**：一般推荐使用 `DATETIME`，避免 2038 年问题。

### 日期函数

```sql
-- 获取当前时间
SELECT NOW(), CURDATE(), CURTIME();

-- 日期格式化
SELECT DATE_FORMAT(created_at, '%Y-%m-%d %H:%i:%s') FROM users;

-- 日期计算
SELECT DATE_ADD(created_at, INTERVAL 7 DAY) FROM users;
SELECT DATEDIFF(NOW(), created_at) FROM users;

-- 提取部分
SELECT YEAR(created_at), MONTH(created_at), DAY(created_at) FROM users;
```

## 四、其他类型

### JSON 类型（MySQL 5.7+）

```sql
CREATE TABLE products (
    id INT PRIMARY KEY,
    name VARCHAR(100),
    attributes JSON
);

INSERT INTO products VALUES (1, '手机', '{"color": "黑色", "storage": "256GB", "ram": "8GB"}');

-- 查询 JSON 字段
SELECT name, JSON_EXTRACT(attributes, '$.color') AS color FROM products;

-- MySQL 8.0+ 简写
SELECT name, attributes->>'$.color' AS color FROM products;

-- JSON 作为虚拟列加索引
ALTER TABLE products ADD COLUMN color VARCHAR(20) GENERATED ALWAYS AS (attributes->>'$.color') STORED;
CREATE INDEX idx_color ON products(color);
```

### ENUM 类型

```sql
status ENUM('pending', 'paid', 'shipped', 'completed')

-- 好处：可读性强
-- 缺点：修改枚举值需要 ALTER TABLE，不灵活
```

**建议**：如果枚举值很少且几乎不变（如性别），可以用 ENUM。否则建议用 `TINYINT` + 注释。

### SET 类型

```sql
permissions SET('read', 'write', 'delete', 'admin')
```

不常用，建议用关联表替代。

## 五、约束类型

### NOT NULL

```sql
name VARCHAR(50) NOT NULL
```

**设计原则**：尽量用 `NOT NULL`，对不确定的字段用 `DEFAULT` 而不是 NULL。

### UNIQUE

```sql
-- 单字段唯一
email VARCHAR(100) UNIQUE NOT NULL

-- 联合唯一：一个用户一天只能发一条评论
UNIQUE KEY uk_user_date (user_id, DATE(created_at))
```

### PRIMARY KEY

```sql
-- 单列主键（推荐自增 BIGINT）
id BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY

-- 复合主键
CREATE TABLE order_items (
    order_id INT,
    product_id INT,
    quantity INT,
    PRIMARY KEY (order_id, product_id)
);
```

### DEFAULT

```sql
status TINYINT NOT NULL DEFAULT 0
created_at DATETIME DEFAULT CURRENT_TIMESTAMP
updated_at DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP
```

### CHECK（MySQL 8.0+ 才真正生效）

```sql
age INT CHECK (age >= 0 AND age <= 150)
price DECIMAL(10,2) CHECK (price >= 0)
status VARCHAR(10) CHECK (status IN ('active', 'inactive'))
```

> 注意：CHECK 约束在 MySQL 8.0.16+ 才真正生效。此前版本语法上支持但被忽略。

### FOREIGN KEY

```sql
order_id INT NOT NULL,
CONSTRAINT fk_order_user FOREIGN KEY (user_id) REFERENCES users(id)
    ON DELETE CASCADE
    ON UPDATE CASCADE
```

外键约束动作：

| 动作 | 说明 |
|------|------|
| `CASCADE` | 级联删除/更新 |
| `SET NULL` | 父表删除时子表设 NULL |
| `RESTRICT` | 禁止删除（默认）|
| `NO ACTION` | 同 RESTRICT |

## 六、字段设计原则

```
id          BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY  -- 主键
user_id     INT UNSIGNED NOT NULL                       -- 外键
xxx_name    VARCHAR(50) NOT NULL                        -- 名称
xxx_status  TINYINT NOT NULL DEFAULT 0                  -- 状态
xxx_at      DATETIME DEFAULT CURRENT_TIMESTAMP           -- 时间字段
```

### 1. NOT NULL 优先

```sql
-- ❌
email VARCHAR(100)

-- ✅
email VARCHAR(100) NOT NULL
-- 如果真不知道，设 DEFAULT ''
```

### 2. 用 TINYINT 代替 ENUM

```sql
-- ❌
status ENUM('pending','paid','cancelled')

-- ✅ （更容易扩展）
status TINYINT NOT NULL DEFAULT 0 COMMENT '0待支付1已支付2已取消'
```

### 3. 时间字段统一

```sql
created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP
updated_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP
```

## 小结

数据类型和约束是表设计的基础。选择合适的数据类型不仅能节省空间，还能提升查询性能。
