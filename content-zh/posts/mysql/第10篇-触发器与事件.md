## 一、触发器（Trigger）

触发器是**自动执行**的存储程序——在表上执行 INSERT、UPDATE、DELETE 操作时自动触发。

### 基本语法

```sql
CREATE TRIGGER trigger_name
{BEFORE | AFTER} {INSERT | UPDATE | DELETE}
ON table_name
FOR EACH ROW
BEGIN
    -- 触发器逻辑
END;
```

### 一个简单的例子

```sql
-- 记录对 users 表的删除操作
DELIMITER //

CREATE TRIGGER before_user_delete
BEFORE DELETE ON users
FOR EACH ROW
BEGIN
    INSERT INTO user_delete_log (user_id, name, email, deleted_at)
    VALUES (OLD.id, OLD.name, OLD.email, NOW());
END //

DELIMITER ;
```

---

### OLD 和 NEW

| 操作 | OLD | NEW |
|------|-----|-----|
| INSERT | ❌ 不存在 | ✅ 新插入的行 |
| UPDATE | ✅ 修改前的行 | ✅ 修改后的行 |
| DELETE | ✅ 被删除的行 | ❌ 不存在 |

```sql
-- 更新触发器：记录修改前后的值
DELIMITER //

CREATE TRIGGER before_user_update
BEFORE UPDATE ON users
FOR EACH ROW
BEGIN
    INSERT INTO user_change_log
        (user_id, field, old_value, new_value, changed_at)
    VALUES
        (NEW.id, 'email', OLD.email, NEW.email, NOW());

    -- 如果修改了手机号，也记录
    IF OLD.phone != NEW.phone THEN
        INSERT INTO user_change_log
            (user_id, field, old_value, new_value, changed_at)
        VALUES
            (NEW.id, 'phone', OLD.phone, NEW.phone, NOW());
    END IF;
END //

DELIMITER ;
```

### 触发器实战场景

#### 1. 自动更新时间戳（简化版）

```sql
CREATE TRIGGER before_users_update
BEFORE UPDATE ON users
FOR EACH ROW
SET NEW.updated_at = NOW();
```

> MySQL 8.0+ 可以直接用 `DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP` 实现，不需要触发器。

#### 2. 库存自动扣减

```sql
CREATE TRIGGER after_order_insert
AFTER INSERT ON order_items
FOR EACH ROW
BEGIN
    UPDATE products
    SET stock = stock - NEW.quantity
    WHERE id = NEW.product_id;
END;
```

> 注意：这种场景用触发器**不推荐**——高并发下可能会超卖。推荐在应用层使用 `UPDATE ... WHERE stock >= quantity` 配合锁。

#### 3. 数据完整性检查

```sql
CREATE TRIGGER before_order_insert
BEFORE INSERT ON orders
FOR EACH ROW
BEGIN
    -- 订单金额不能为负
    IF NEW.total_amount < 0 THEN
        SIGNAL SQLSTATE '45000'
        SET MESSAGE_TEXT = '订单金额不能为负';
    END IF;

    -- 订单号必填
    IF NEW.order_no IS NULL OR NEW.order_no = '' THEN
        SIGNAL SQLSTATE '45000'
        SET MESSAGE_TEXT = '订单号不能为空';
    END IF;
END;
```

#### 4. 审计日志

```sql
CREATE TRIGGER after_user_update
AFTER UPDATE ON users
FOR EACH ROW
BEGIN
    INSERT INTO audit_log (table_name, record_id, action, old_data, new_data, created_at)
    VALUES (
        'users',
        NEW.id,
        'UPDATE',
        JSON_OBJECT('name', OLD.name, 'email', OLD.email),
        JSON_OBJECT('name', NEW.name, 'email', NEW.email),
        NOW()
    );
END;
```

### 触发器管理

```sql
-- 查看触发器
SHOW TRIGGERS;

-- 查看触发器定义
SHOW CREATE TRIGGER before_user_delete;

-- 查看 information_schema
SELECT * FROM information_schema.TRIGGERS
WHERE TRIGGER_SCHEMA = 'shop';

-- 删除触发器
DROP TRIGGER IF EXISTS before_user_delete;
```

### 触发器的限制

| 限制 | 说明 |
|------|------|
| 一个表最多 6 个触发器 | 每类事件（BEFORE/AFTER × INSERT/UPDATE/DELETE）各一个 |
| 不能递归 | 触发器不能自己调用自己 |
| 隐式提交 | 触发器中不能使用事务控制语句（START TRANSACTION、COMMIT、ROLLBACK）|
| 性能影响 | 每个 DML 操作都会增加额外开销 |
| 难调试 | 触发器的行为是隐式的，可能让人困惑 |

### 什么时候该用触发器？

| ✅ 适合 | ❌ 不适合 |
|---------|----------|
| 审计日志 | 复杂业务逻辑 |
| 简单数据校验 | 跨服务调用 |
| 自动维护衍生数据 | 高频写入场景（会放大写入开销）|
| 简单的数据同步 | 高并发扣库存 |

**经验法则**：能不用的地方尽量不用。很多触发器能干的事，在应用层做更可控、更易维护。

## 二、事件（Event）

事件是 MySQL 的**定时任务**，按照指定时间表自动执行 SQL。

### 开启事件调度器

```sql
-- 查看是否开启
SHOW VARIABLES LIKE 'event_scheduler';

-- 开启（临时）
SET GLOBAL event_scheduler = ON;

-- 配置中永久开启（my.cnf）
-- event_scheduler = ON
```

### 创建事件

```sql
DELIMITER //

CREATE EVENT daily_cleanup
ON SCHEDULE EVERY 1 DAY
STARTS '2025-01-01 03:00:00'
DO
BEGIN
    -- 删除 90 天前的日志
    DELETE FROM operation_logs WHERE created_at < NOW() - INTERVAL 90 DAY;

    -- 将过期未支付订单标记为已取消
    UPDATE orders SET status = 4
    WHERE status = 0 AND created_at < NOW() - INTERVAL 1 DAY;
END //

DELIMITER ;
```

### 事件调度配置

```sql
-- 一次性事件
CREATE EVENT one_time_cleanup
ON SCHEDULE AT '2025-02-01 02:00:00'
DO
    DELETE FROM temp_data WHERE created_at < NOW();

-- 重复事件
CREATE EVENT hourly_stats
ON SCHEDULE EVERY 1 HOUR
STARTS '2025-01-01 00:00:00'
ENDS '2025-12-31 23:59:59'
DO
    INSERT INTO hourly_orders (hour, order_count, total_amount)
    SELECT DATE_FORMAT(NOW(), '%Y-%m-%d %H:00:00'), COUNT(*), SUM(total_amount)
    FROM orders
    WHERE created_at >= NOW() - INTERVAL 1 HOUR;

-- 每 5 分钟执行
CREATE EVENT every_5_minutes
ON SCHEDULE EVERY 5 MINUTE
DO
    CALL process_pending_jobs();
```

### 事件管理

```sql
-- 查看事件
SHOW EVENTS;
SHOW EVENTS FROM shop;

-- 查看事件定义
SHOW CREATE EVENT daily_cleanup;

-- 修改事件
ALTER EVENT daily_cleanup
ON SCHEDULE EVERY 6 HOUR;

-- 启用/禁用
ALTER EVENT daily_cleanup ENABLE;
ALTER EVENT daily_cleanup DISABLE;

-- 删除
DROP EVENT IF EXISTS daily_cleanup;
```

### 事件状态检查

```sql
-- 查看事件执行历史
SELECT * FROM information_schema.EVENTS
WHERE EVENT_SCHEMA = 'shop';

-- 查看进程列表
SHOW PROCESSLIST;
-- 会看到一个 event_scheduler 线程
```

## 三、实战场景

### 场景一：自动过期清理

```sql
CREATE EVENT clean_expired_sessions
ON SCHEDULE EVERY 30 MINUTE
DO
BEGIN
    -- 清理过期会话
    DELETE FROM sessions WHERE expires_at < NOW();

    -- 清理未验证的用户（超过 24 小时没验证邮箱）
    UPDATE users SET status = -1
    WHERE status = 0 AND email_verified_at IS NULL
      AND created_at < NOW() - INTERVAL 24 HOUR;

    -- 释放已取消订单的库存
    UPDATE products p
    JOIN order_items oi ON oi.product_id = p.id
    JOIN orders o ON o.id = oi.order_id
    SET p.stock = p.stock + oi.quantity
    WHERE o.status = 4 AND o.updated_at < NOW() - INTERVAL 1 HOUR;
END;
```

### 场景二：日报自动生成

```sql
CREATE EVENT generate_daily_summary
ON SCHEDULE EVERY 1 DAY
STARTS '2025-01-01 23:55:00'
DO
BEGIN
    INSERT INTO daily_summary (summary_date, new_users, new_orders, revenue)
    SELECT
        CURDATE() - INTERVAL 1 DAY,
        (SELECT COUNT(*) FROM users WHERE DATE(created_at) = CURDATE() - INTERVAL 1 DAY),
        (SELECT COUNT(*) FROM orders WHERE DATE(created_at) = CURDATE() - INTERVAL 1 DAY),
        (SELECT COALESCE(SUM(total_amount), 0) FROM orders
         WHERE DATE(paid_at) = CURDATE() - INTERVAL 1 DAY AND status = 1);
END;
```

### 场景三：定期数据归档

```sql
CREATE EVENT archive_old_orders
ON SCHEDULE EVERY 1 MONTH
STARTS '2025-02-01 04:00:00'
DO
BEGIN
    -- 将一年前的订单移到归档表
    INSERT INTO orders_archive
    SELECT * FROM orders
    WHERE created_at < NOW() - INTERVAL 1 YEAR
      AND NOT EXISTS (SELECT 1 FROM orders_archive oa WHERE oa.id = orders.id);

    -- 删除已归档的原数据
    DELETE FROM orders
    WHERE created_at < NOW() - INTERVAL 1 YEAR;
END;
```

## 四、事件 vs 系统定时任务

| 对比 | MySQL Event | 系统 cron |
|------|------------|-----------|
| 依赖 | MySQL 实例必须运行 | 系统 crond |
| 延迟 | 精确到秒 | 精确到分钟 |
| 管理 | SQL 操作，方便 | 需要 SSH |
| 备份 | 包含在 DB 备份中 | 需要额外备份 |
| 资源 | 使用 DB 连接 | 独立进程 |

**建议**：
- 简单的数据库维护任务 → MySQL Event
- 复杂的跨系统任务 → 系统 cron（如调用外部 API、发送邮件）

---

## 小结

触发器和事件是 MySQL 的自动化能力。触发器适合简单的数据完整性检查和审计，事件用于数据库内定时任务。注意控制触发器的使用范围，避免隐式逻辑导致的问题。
