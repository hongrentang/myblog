## 一、什么是事务？

事务是一组 SQL 操作，要么全部成功，要么全部失败回滚。

```sql
-- 银行转账的例子
START TRANSACTION;

UPDATE accounts SET balance = balance - 1000 WHERE id = 1;
UPDATE accounts SET balance = balance + 1000 WHERE id = 2;

COMMIT;  -- 提交
-- 或
ROLLBACK;  -- 回滚
```

如果第一条 UPDATE 成功后服务器宕机，事务机制保证第二条不会执行，数据保持一致性。

---

## 二、ACID 特性

| 特性 | 含义 | 实现机制 |
|------|------|---------|
| **A**tomicity（原子性）| 事务不可分割，要么全做要么全不做 | undo log |
| **C**onsistency（一致性）| 事务前后数据满足所有约束 | 应用层 + 数据库约束 |
| **I**solation（隔离性）| 并发事务互不干扰 | 锁 + MVCC |
| **D**urability（持久性）| 提交后数据永久保存 | redo log |

## 三、事务隔离级别

SQL 标准定义了四种隔离级别，从低到高：

```sql
-- 查看当前隔离级别
SELECT @@transaction_isolation;
-- MySQL 8.0 默认：REPEATABLE-READ

-- 设置隔离级别
SET SESSION TRANSACTION ISOLATION LEVEL READ COMMITTED;
```

| 隔离级别 | 脏读 | 不可重复读 | 幻读 | 说明 |
|---------|------|-----------|------|------|
| `READ UNCOMMITTED` | ✅ 可能 | ✅ 可能 | ✅ 可能 | 能读到未提交的数据 |
| `READ COMMITTED` | ❌ | ✅ 可能 | ✅ 可能 | 只读已提交（Oracle 默认）|
| `REPEATABLE READ` | ❌ | ❌ | ✅ 可能 | 同一事务内多次读取一致（MySQL 默认）|
| `SERIALIZABLE` | ❌ | ❌ | ❌ | 串行化，最安全但最慢 |

### 脏读

事务 A 读到事务 B **未提交**的数据，如果 B 回滚，A 就读了不存在的数据。

### 不可重复读

同一事务内两次读取同一行，结果不一样。

```
事务 A: SELECT name FROM users WHERE id = 1 → '张三'
事务 B: UPDATE users SET name = '李四' WHERE id = 1; COMMIT;
事务 A: SELECT name FROM users WHERE id = 1 → '李四'
```

### 幻读

同一事务内两次范围查询，第二次多了或少了几行。

```
事务 A: SELECT * FROM orders WHERE amount > 100  → 5 行
事务 B: INSERT INTO orders (amount) VALUES (200); COMMIT;
事务 A: SELECT * FROM orders WHERE amount > 100  → 6 行（多了 1 行）
```

## 四、MVCC（多版本并发控制）

InnoDB 通过 **MVCC** 实现 `REPEATABLE READ` 级别，**在不加锁的情况下**解决不可重复读问题。

### 核心原理

每行数据可能有多个版本（多个快照），每个事务看到的是自己"快照"时刻的数据版本。

```sql
-- 数据行其实包含两个隐藏列：
-- DB_TRX_ID：最后修改该行的事务 ID
-- DB_ROLL_PTR：指向 undo log 的指针，用于找到旧版本
```

### Read View

事务开始时会生成一个 **Read View**，记录了当时活跃的事务列表：

```
Read View
├── creator_trx_id：当前事务 ID
├── m_ids：活跃事务 ID 列表
├── min_trx_id：活跃事务最小 ID
└── max_trx_id：下一个要分配的事务 ID
```

**可见性规则**：

```
某行数据的 DB_TRX_ID：
├── < min_trx_id       → 已提交，可见
├── = creator_trx_id   → 自己修改的，可见
├── > max_trx_id       → 未来的事务，不可见
├── 在 m_ids 中        → 未提交，不可见
└── 不在 m_ids 中      → 已提交，可见
```

### MVCC 解决了什么？

- ✅ 脏读：未提交事务的修改对其他事务不可见
- ✅ 不可重复读：同一事务多次查询使用同一个 Read View
- ❌ 幻读：MVCC 不能完全解决（但 InnoDB 用间隙锁在部分场景下解决了）

## 五、行锁（Record Lock）

对索引记录加锁，阻止其他事务修改或删除。

```sql
-- 共享锁（S Lock）：允许多个事务同时读，阻止写
SELECT * FROM users WHERE id = 1 LOCK IN SHARE MODE;

-- 排他锁（X Lock）：阻止其他事务读和写
SELECT * FROM users WHERE id = 1 FOR UPDATE;
```

### 行锁的三种算法

```sql
-- InnoDB 行锁基于索引实现，锁定的是索引记录
```

**Record Lock**：单行记录锁

```sql
-- 锁定 id = 1 这一行
SELECT * FROM users WHERE id = 1 FOR UPDATE;
```

**Gap Lock**：间隙锁，锁住记录之间的间隙，阻止插入

```sql
-- 假设 users 表有 id: 1, 3, 5
SELECT * FROM users WHERE id BETWEEN 2 AND 4 FOR UPDATE;
-- 锁住 (1,3) 和 (3,5) 之间的间隙，不能插入 id=2,4
```

**Next-Key Lock**：Record Lock + Gap Lock 的组合

```sql
-- InnoDB RR 级别的默认锁机制
-- 锁住记录本身 + 前面的间隙
```

## 六、表锁

### 表级锁

```sql
-- 手动加表锁
LOCK TABLES users READ;     -- 读锁，其他会话可读不可写
LOCK TABLES users WRITE;    -- 写锁，其他会话不可读写

UNLOCK TABLES;
```

### 意向锁

InnoDB 自动管理，不需要手动操作。当事务要给某行加行锁时，自动在表级别加意向锁，快速判断表是否已被其他事务锁住。

```
意向共享锁（IS）：准备给某些行加共享锁
意向排他锁（IX）：准备给某些行加排他锁
```

## 七、死锁

两个事务互相等待对方释放锁：

```sql
-- 事务 A
START TRANSACTION;
UPDATE accounts SET balance = balance - 100 WHERE id = 1;  -- 锁住 id=1
UPDATE accounts SET balance = balance + 100 WHERE id = 2;  -- 等待 B 释放 id=2

-- 事务 B
START TRANSACTION;
UPDATE accounts SET balance = balance - 100 WHERE id = 2;  -- 锁住 id=2
UPDATE accounts SET balance = balance + 100 WHERE id = 1;  -- 等待 A 释放 id=1
```

### InnoDB 处理死锁

```sql
-- 查看死锁信息
SHOW ENGINE INNODB STATUS\G

-- InnoDB 会自动检测死锁并回滚其中一个事务（回滚代价较小的那个）
```

### 避免死锁

```sql
-- 1. 按相同顺序访问资源
-- ❌ 可能死锁
UPDATE accounts SET ... WHERE id = 1;
UPDATE accounts SET ... WHERE id = 2;
-- 另一个事务：
UPDATE accounts SET ... WHERE id = 2;
UPDATE accounts SET ... WHERE id = 1;

-- ✅ 固定顺序
UPDATE accounts SET ... WHERE id = 1;
UPDATE accounts SET ... WHERE id = 2;
-- 另一个事务也按 id 升序

-- 2. 缩短事务时间
-- 3. 使用 READ COMMITTED 减少间隙锁
```

## 八、事务实战

### 正确的异常处理

```sql
-- 存储过程
CREATE PROCEDURE transfer(IN from_id INT, IN to_id INT, IN amount DECIMAL(10,2))
BEGIN
    DECLARE EXIT HANDLER FOR SQLEXCEPTION
    BEGIN
        ROLLBACK;
        RESIGNAL;
    END;

    START TRANSACTION;

    UPDATE accounts SET balance = balance - amount WHERE id = from_id;
    UPDATE accounts SET balance = balance + amount WHERE id = to_id;

    COMMIT;
END;
```

### 设置超时

```sql
-- 锁等待超时（默认 50 秒）
SET innodb_lock_wait_timeout = 10;  -- 10 秒

-- 事务超时
SET SESSION max_execution_time = 5000;  -- 5 秒
```

### 查看锁信息

```sql
-- 查看当前锁等待
SELECT * FROM performance_schema.data_lock_waits\G

-- 查看事务
SELECT * FROM information_schema.INNODB_TRX\G
```

## 九、隔离级别的选择建议

| 场景 | 推荐隔离级别 | 原因 |
|------|-------------|------|
| 默认 | REPEATABLE READ | MySQL 默认，MVCC 支持好 |
| 高并发系统 | READ COMMITTED | 减少间隙锁，提升并发性能 |
| 财务系统 | REPEATABLE READ 或 SERIALIZABLE | 数据一致性要求高 |
| 报表分析 | READ UNCOMMITTED | 允许脏读，减少锁等待 |

```sql
-- 高并发系统推荐：READ COMMITTED + binlog_row_image=MINIMAL
SET GLOBAL transaction_isolation = 'READ-COMMITTED';
```
