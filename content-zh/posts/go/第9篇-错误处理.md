## 错误处理哲学

Go 没有异常（try-catch），错误就是普通的值。

**设计思想**：

```
错误是值，不是异常
显式错误处理，而不是隐式抛出
每个可能出错的地方都应该处理
```

---

## 一、error 接口

error 是 Go 内置的接口：

```go
type error interface {
    Error() string
}
```

任何实现了 `Error() string` 方法的类型都是 error。

### 基本用法

```go
// 返回 error 的函数
func divide(a, b float64) (float64, error) {
    if b == 0 {
        return 0, errors.New("除数不能为 0")
    }
    return a / b, nil
}

// 调用时处理
result, err := divide(10, 0)
if err != nil {
    fmt.Println("出错了:", err)
    return
}
fmt.Println(result)
```

## 二、创建错误

### errors.New

```go
import "errors"

var ErrNotFound = errors.New("记录未找到")
var ErrPermission = errors.New("权限不足")

func findUser(id int) (*User, error) {
    if id <= 0 {
        return nil, ErrNotFound
    }
    // ...
}
```

### fmt.Errorf

```go
// 格式化错误
func validateAge(age int) error {
    if age < 0 || age > 150 {
        return fmt.Errorf("无效年龄: %d", age)
    }
    return nil
}

// %w 包装错误（Go 1.13+）
func process() error {
    err := doSomething()
    if err != nil {
        return fmt.Errorf("处理失败: %w", err)  // %w 包装原始错误
    }
    return nil
}
```

## 三、自定义错误类型

### 带额外信息的错误

```go
type ValidationError struct {
    Field   string
    Value   interface{}
    Message string
}

func (e *ValidationError) Error() string {
    return fmt.Sprintf("字段 %s 校验失败: %s (值: %v)",
        e.Field, e.Message, e.Value)
}

func validateUser(u User) error {
    if u.Name == "" {
        return &ValidationError{
            Field:   "Name",
            Value:   u.Name,
            Message: "名称不能为空",
        }
    }
    return nil
}

// 使用类型断言获取详细信息
err := validateUser(user)
var ve *ValidationError
if errors.As(err, &ve) {
    fmt.Printf("校验失败: %s (%s)\n", ve.Field, ve.Message)
}
```

### 带错误码

```go
type AppError struct {
    Code    int
    Message string
    Err     error
}

func (e *AppError) Error() string {
    return fmt.Sprintf("[%d] %s: %v", e.Code, e.Message, e.Err)
}

func (e *AppError) Unwrap() error {
    return e.Err
}

func NewAppError(code int, msg string, err error) *AppError {
    return &AppError{Code: code, Message: msg, Err: err}
}
```

## 四、错误处理模式

### 基本模式

```go
// 标准模式：if err != nil
data, err := fetchData()
if err != nil {
    log.Printf("fetchData error: %v", err)
    return nil, err
}
```

### 包装模式

```go
// 逐层包装，保留栈信息
func LoadConfig(path string) (*Config, error) {
    file, err := os.Open(path)
    if err != nil {
        return nil, fmt.Errorf("打开配置文件失败 %s: %w", path, err)
    }
    defer file.Close()

    var cfg Config
    if err := json.NewDecoder(file).Decode(&cfg); err != nil {
        return nil, fmt.Errorf("解析配置失败: %w", err)
    }
    return &cfg, nil
}
```

### 快速失败

```go
// 如果启动配置错了，直接 panic
func init() {
    cfg, err := LoadConfig("config.json")
    if err != nil {
        panic(fmt.Sprintf("加载配置失败: %v", err))
    }
}
```

### 重试模式

```go
func fetchWithRetry(url string, maxRetries int) (*Response, error) {
    var lastErr error
    for i := 0; i < maxRetries; i++ {
        resp, err := http.Get(url)
        if err == nil {
            return resp, nil
        }
        lastErr = err
        time.Sleep(time.Second * time.Duration(i+1))
    }
    return nil, fmt.Errorf("重试 %d 次后失败: %w", maxRetries, lastErr)
}
```

## 五、errors 包

Go 1.13+ 的 errors 包提供了三个关键函数：

### errors.Is

```go
if errors.Is(err, ErrNotFound) {
    // 判断错误链中是否有 ErrNotFound
}
```

### errors.As

```go
var ve *ValidationError
if errors.As(err, &ve) {
    // 找出错误链中第一个匹配类型的错误
    fmt.Println(ve.Field)
}
```

### errors.Unwrap

```go
// 解包一层
innerErr := errors.Unwrap(err)
```

### 完整示例

```go
// 各层包装
func readConfig() error {
    return fmt.Errorf("读取配置: %w", ErrNotFound)
}

func process() error {
    return fmt.Errorf("处理失败: %w", readConfig())
}

func main() {
    err := process()
    fmt.Println(err)                    // 处理失败: 读取配置: 记录未找到

    fmt.Println(errors.Is(err, ErrNotFound))  // true（遍历错误链）
    fmt.Println(errors.Is(err, os.ErrNotExist)) // false
}
```

## 六、panic 和 recover

### panic

panic 是 Go 的运行时异常机制，通常用于**不可恢复的错误**：

```go
// 什么时候用 panic：
// 1. 程序状态严重异常，继续运行毫无意义
// 2. 程序员错误（如索引越界）
// 3. 启动时依赖缺失

func must(err error) {
    if err != nil {
        panic(err)
    }
}

func init() {
    cfg, err := LoadConfig()
    must(err)  // 启动失败，直接 panic
}
```

### recover

```go
// recover 只能放在 defer 中
func safeRun(f func()) {
    defer func() {
        if r := recover(); r != nil {
            fmt.Println("程序崩溃，已恢复:", r)
        }
    }()
    f()
}

// 实战：HTTP handler 中的 recover
func RecoveryMiddleware(next http.Handler) http.Handler {
    return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
        defer func() {
            if err := recover(); err != nil {
                log.Printf("panic recovered: %v\n", err)
                http.Error(w, "Internal Server Error", 500)
            }
        }()
        next.ServeHTTP(w, r)
    })
}
```

### 链式调用中的 recover

```go
type Chain struct {
    steps []func() error
}

func (c *Chain) Add(step func() error) {
    c.steps = append(c.steps, step)
}

func (c *Chain) Run() (err error) {
    defer func() {
        if r := recover(); r != nil {
            err = fmt.Errorf("pipeline panic: %v", r)
        }
    }()
    for _, step := range c.steps {
        if err := step(); err != nil {
            return fmt.Errorf("step failed: %w", err)
        }
    }
    return nil
}
```

## 七、错误处理最佳实践

```
错误处理原则：
1. 错误就是值——像处理普通值一样处理
2. 总是处理错误——不要 _
3. 包装错误保留上下文——用 %w
4. 区分可恢复和不可恢复错误
5. 创建哨兵错误（sentinel errors）用 Err 前缀
6. 不要重复记录错误——每层或记录或包装，不要既记录又包装
```

### 好的 vs 不好的

```go
// ❌ 忽略错误
data, _ := doSomething()

// ❌ 多次记录
func read() error {
    err := os.ReadFile("file")
    log.Println(err)   // 下层记录
    return err
}
func main() {
    err := read()
    log.Println(err)   // 上层又记录
}

// ✅ 正确的做法：只记录一次
func read() error {
    return fmt.Errorf("读取文件: %w", os.ReadFile("file"))
}
func main() {
    err := read()
    if err != nil {
        log.Println(err)  // 只在最外层记录
    }
}
```

## 小结

Go 的错误处理简单直接——错误就是值。核心习惯：**if err != nil**、**包装错误上下文**、**只在最外层记录日志**。Panic 只用于真正的异常情况，用 recover 作为安全网。
