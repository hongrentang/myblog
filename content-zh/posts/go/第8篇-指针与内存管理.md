## 一、指针

Go 有指针，但没有指针运算（不像 C 语言可以 `p++`）。

### 基本用法

```go
var x int = 10
var p *int = &x  // p 指向 x 的地址

fmt.Println(p)   // 0xc0000a0000（地址）
fmt.Println(*p)  // 10（解引用）
```

### new 函数

```go
// new 分配内存，返回指针
p := new(int)    // *int，默认值 0
*p = 100

// 等价于
var x int
p := &x
```

### 指针作为参数

```go
func swap(a, b *int) {
    *a, *b = *b, *a
}

x, y := 1, 2
swap(&x, &y)
fmt.Println(x, y)  // 2 1
```

### 指针 vs 值

```go
// 值传递——拷贝
func byValue(u User) {
    u.Name = "改不了"
}

// 指针传递——修改原数据
func byPointer(u *User) {
    u.Name = "改得了"
}

u := User{Name: "张三"}
byValue(u)
fmt.Println(u.Name)    // 张三

byPointer(&u)
fmt.Println(u.Name)    // 改得了
```

## 二、new vs make

| 对比 | new | make |
|------|-----|------|
| 作用 | 分配内存 | 初始化内置引用类型 |
| 返回 | 指针（*T）| 值（slice/map/channel）|
| 适用 | 任意类型 | 仅 slice、map、channel |
| 初始化 | 零值 | 分配底层数据结构 |

```go
p := new([]int)      // *[]int（nil 切片）
fmt.Println(*p == nil)  // true

v := make([]int, 5)  // []int 值，底层已分配
fmt.Println(v)       // [0 0 0 0 0]

// 常见模式：创建返回指针的结构体
func NewUser(name string) *User {
    return &User{Name: name}  // Go 编译器自动分配到堆上
}
```

## 三、栈 vs 堆

### 逃逸分析（Escape Analysis）

Go 的编译器会分析变量应该分配在栈上还是堆上：

```go
// 栈分配——变量不会逃逸
func sum() int {
    x := 10
    y := 20
    return x + y  // x, y 不会逃逸，在栈上分配
}

// 堆分配——变量逃逸到堆
func newUser() *User {
    u := User{Name: "张三"}  // 因为返回了指针，u 逃逸到堆上
    return &u
}
```

### 查看逃逸分析

```bash
go build -gcflags '-m' main.go

# 输出示例：
# ./main.go:10:2: moved to heap: u
```

### 为什么关心逃逸？

| 分配位置 | 优点 | 缺点 |
|---------|------|------|
| 栈 | 零 GC 开销，自动回收 | 生命周期短 |
| 堆 | 生命周期灵活 | GC 有开销 |

### 减少不必要的堆分配

```go
// ❌ 返回指针导致逃逸
func getValue(m map[string]int, key string) *int {
    v := m[key]
    return &v  // v 逃逸到堆
}

// ✅ 返回值类型
func getValue(m map[string]int, key string) int {
    return m[key]  // 栈分配
}
```

## 四、GC（垃圾回收）

Go 使用**并发三色标记清除**算法。

### GC 触发条件

```go
// 1. 堆内存增长到一定比例
// 2. 超过 2 分钟没 GC
// 3. 手动调用
runtime.GC()
```

### GC 调试

```go
// 查看 GC 统计
var m runtime.MemStats
runtime.ReadMemStats(&m)

fmt.Printf("分配内存: %d MB\n", m.Alloc/1024/1024)
fmt.Printf("总分配: %d MB\n", m.TotalAlloc/1024/1024)
fmt.Printf("GC 次数: %d\n", m.NumGC)
fmt.Printf("下一次 GC 触发: %d MB\n", m.NextGC/1024/1024)

// GODEBUG 环境变量
// GODEBUG=gctrace=1 ./myapp
// gc 1 @0.003s 4%: 0.022+0.18+0.009 ms clock, 0.17+0.23/0.37/0+0.073 ms cpu, 4->4->0 MB, 5 MB goal, 4 P
```

## 五、unsafe 包

日常开发中**尽量避免使用**，只在特殊场景才用：

```go
import "unsafe"

func main() {
    x := int32(10)
    size := unsafe.Sizeof(x)
    fmt.Println(size)  // 4

    // 指针转换（危险！）
    var f float64 = 3.14
    // 将 float64 指针转为 int64 指针（不推荐）
    i := *(*int64)(unsafe.Pointer(&f))
    fmt.Println(i)
}
```

## 六、常见内存问题

### 1. 内存泄漏

```go
// 切片引用大数组，释放不掉
func process() {
    data := readLargeFile()  // 大数组
    result := data[:10]      // 小切片引用大数组
    // data 不能 GC，因为被 result 引用
}

// 修正：用 copy
func process() {
    data := readLargeFile()
    result := make([]byte, 10)
    copy(result, data[:10])  // result 独立，data 可被 GC
}
```

### 2. Goroutine 泄漏

```go
// ❌ goroutine 永远阻塞
func leak() {
    ch := make(chan int)
    go func() {
        <-ch  // 永远等待
    }()
}

// ✅ 用 context 超时控制
func noLeak(ctx context.Context) {
    ch := make(chan int)
    go func() {
        select {
        case <-ch:
        case <-ctx.Done():
        }
    }()
}
```

## 七、内存优化建议

```go
// 1. 预分配切片容量
// ❌
var s []int
for i := 0; i < 10000; i++ {
    s = append(s, i)
}

// ✅
s := make([]int, 0, 10000)
for i := 0; i < 10000; i++ {
    s = append(s, i)
}

// 2. 复用对象（sync.Pool）
var pool = sync.Pool{
    New: func() interface{} {
        return &bytes.Buffer{}
    },
}

func write(w io.Writer) {
    buf := pool.Get().(*bytes.Buffer)
    buf.Reset()
    defer pool.Put(buf)

    // 使用 buf...
    w.Write(buf.Bytes())
}

// 3. 避免大的栈复制
// 大结构体用指针传递

// 4. 减少字符串拼接
// ❌
s := ""
for i := 0; i < 1000; i++ {
    s += "a"
}
// O(n²)，每次都创建新字符串

// ✅
var b strings.Builder
for i := 0; i < 1000; i++ {
    b.WriteString("a")
}
s := b.String()  // O(n)，预分配缓冲区
```

## 小结

Go 的指针简单安全（没有指针运算），配合逃逸分析和 GC 自动管理内存。日常开发不需要过分关注内存分配，但在性能敏感场景中，了解逃逸分析和减少堆分配会很有帮助。
