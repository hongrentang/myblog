## 一、Go Module 简介

Go Module 是 Go 1.11 引入的官方依赖管理方案，从 Go 1.16 起成为默认方式。

**核心文件**：

```
myproject/
├── go.mod      # 模块定义和依赖声明
├── go.sum      # 依赖的校验和（自动管理）
└── main.go
```

---

## 二、go.mod 文件

### 初始化

```bash
# 创建新项目
mkdir myapp && cd myapp
go mod init myapp

# 生成的 go.mod：
module myapp

go 1.23
```

### 添加依赖

```bash
# 方式1：go get
go get github.com/gin-gonic/gin

# 方式2：import 后 go mod tidy
# 在代码中 import "github.com/gin-gonic/gin"
go mod tidy  # 自动添加缺失的依赖，移除未使用的

# 安装特定版本
go get github.com/gin-gonic/gin@v1.10.0
```

### go.mod 内容示例

```
module github.com/user/myapp

go 1.23

require (
    github.com/gin-gonic/gin v1.10.0
    github.com/go-sql-driver/mysql v1.8.1
)

require (
    github.com/bytedance/sonic v1.11.6 // indirect
    github.com/gabriel-vasile/mimetype v1.4.3 // indirect
)
```

- `indirect`：间接依赖（非直接 import 的）
- `//` 后面的注释是自动生成的

## 三、包的导入

### 导入语法

```go
// 单个导入
import "fmt"

// 分组导入
import (
    "fmt"
    "os"

    "github.com/gin-gonic/gin"
    "github.com/go-sql-driver/mysql"
)

// 别名
import f "fmt"

// 点导入（不推荐，会污染命名空间）
import . "fmt"

// 匿名导入（仅执行 init，不使用包中的标识符）
import _ "github.com/go-sql-driver/mysql"
```

### 导入路径

```go
// 标准库
import "fmt"
import "net/http"
import "encoding/json"

// 第三方
import "github.com/gin-gonic/gin"

// 内部包
import "myapp/internal/database"
import "myapp/pkg/utils"
```

## 四、包的可见性

Go 通过**首字母大小写**控制可见性：

```go
// 包 myapp/pkg/utils

// 首字母大写 = 导出的（公有）
func PublicFunc() {}

// 首字母小写 = 非导出的（私有）
func privateFunc() {}

// 同样适用于变量、常量、结构体、接口
var PublicVar = 1
var privateVar = 2

type PublicStruct struct{}
type privateStruct struct{}
```

### 包内 vs 包外

```go
// 同一个包内，可以访问所有内容
// a.go
package utils
var internalVar = 10

// b.go（同一个包）
package utils
func getVar() int {
    return internalVar  // ✅ 同一个包，私有也可访问
}
```

## 五、包的组织结构

### 标准 Go 项目布局

```
myapp/
├── go.mod
├── go.sum
├── main.go                    # 入口文件
├── cmd/                       # 可执行文件
│   └── server/
│       └── main.go
├── internal/                  # 私有包（外部无法导入）
│   ├── database/
│   │   └── db.go
│   └── config/
│       └── config.go
├── pkg/                       # 对外公开的包
│   └── response/
│       └── response.go
├── api/                       # API 定义
├── web/                       # 前端资源
└── scripts/                   # 构建脚本
```

### internal 包的特殊性

`internal` 目录下的包只能被其父目录树内的代码导入：

```
myapp/
├── internal/     # 只有 myapp 内的代码可以导入
│   └── secret/
└── main.go       # ✅ 可以导入 internal/secret

other/
└── main.go       # ❌ 不能导入 myapp/internal/secret
```

## 六、依赖管理

### 常用命令

```bash
# 添加依赖
go get github.com/gin-gonic/gin

# 更新依赖
go get -u github.com/gin-gonic/gin
go get -u ./...       # 更新所有依赖

# 清理依赖
go mod tidy

# 下载所有依赖到本地缓存
go mod download

# 查看依赖
go list -m all                 # 所有依赖
go list -m -versions github.com/gin-gonic/gin  # 查看可用的版本

# 查看为什么依赖了某个包
go mod why github.com/gin-gonic/gin

# 验证依赖
go mod verify

# 可视化依赖图
go mod graph
```

### 版本管理

```bash
# 升级到次要版本
go get github.com/gin-gonic/gin@latest

# 指定版本
go get github.com/gin-gonic/gin@v1.10.0

# 升级到主版本 v2
go get github.com/gin-gonic/gin/v2
```

### 替换本地依赖

```go
// go.mod 中使用 replace 指令
module myapp

go 1.23

require (
    github.com/example/mypackage v0.0.0
)

// 用本地路径替换
replace github.com/example/mypackage => ../mypackage
```

## 七、vendor 目录

```bash
# 将依赖拷贝到 vendor 目录
go mod vendor

# 构建时使用 vendor
go build -mod=vendor

# 项目在构建时需要离线环境时很有用
```

**go vendor 和 go.sum 配合**：vendor 目录记录依赖的完整副本，go.sum 记录完整性哈希。

## 七、常见问题

### 1. 导入冲突

```go
// 两个不同的包有相同的名字
import (
    "crypto/rand"
    "math/rand"
)

// 用别名解决
import (
    cryptorand "crypto/rand"
    "math/rand"
)
```

### 2. 循环导入

```
a.go import b  →  b.go import a  →  编译错误
```

**解决方法**：
1. 提取公共接口到第三个包
2. 调整包职责，消除循环依赖

### 3. 私有仓库

```bash
# Go 代理不支持私有仓库
GOPROXY=direct

# 或配置私有仓库不走代理
go env -w GOPRIVATE=github.com/mycompany/*
go env -w GONOSUMCHECK=github.com/mycompany/*  # 跳过校验
```

## 八、Go Proxy

```bash
# 默认代理
go env -w GOPROXY=https://proxy.golang.org,direct

# 国内镜像（推荐）
go env -w GOPROXY=https://goproxy.cn,direct

# 直接连接（不使用代理）
go env -w GOPROXY=direct

# 多代理
go env -w GOPROXY=https://goproxy.cn,https://goproxy.io,direct
```

## 九、构建与跨平台编译

```bash
# 构建当前平台
go build -o myapp main.go

# Linux
GOOS=linux GOARCH=amd64 go build -o myapp-linux main.go

# Windows
GOOS=windows GOARCH=amd64 go build -o myapp.exe main.go

# macOS
GOOS=darwin GOARCH=amd64 go build -o myapp-mac main.go
GOOS=darwin GOARCH=arm64 go build -o myapp-mac-m1 main.go  # Apple Silicon

# 禁用 CGO
CGO_ENABLED=0 go build -o myapp main.go

# 减小编译体积
go build -ldflags="-s -w" -o myapp main.go

# 查看支持的平台
go tool dist list
```

## 小结

包管理是 Go 项目组织的基础。Go Module 让依赖管理变得简单：`go mod init` 初始化，`go get` 添加依赖，`go mod tidy` 清理整理。合理的包结构（internal、pkg）让代码组织更清晰。
